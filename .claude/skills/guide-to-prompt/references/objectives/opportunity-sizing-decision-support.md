# Opportunity Sizing & Decision Support

**Axis 1 analytical objective.** Canonical label, do not rename it and do not invent new ones. It is
an objective, never a domain, so the build draws its domain from the six. Fingerprint card key:
`opportunity-sizing-decision`.

> The headline figure is a sized opportunity (addressable volume, value at stake, headroom or recoverable value), built up from the addressable pool to what can actually be realised, and that sizing drives a committed decision.

**Discriminating test.** If the prompt could be retagged Forecasting & Predictive Modeling or
Descriptive & Distribution Analysis without changing a word, it does not earn the tag.

## Where the examples live

The worked prompts are filed by **prompt shape** in `../shapes/`, written in the current format:
prose, first person, one committed call, one to three named files, and the generated rubric's 25
criteria coming from the structure of the answer rather than from a list of asks. The client's own
example page tags many of those worked prompts with this label, but the label is not carried on the
imported examples, so the shape files do not mark which ones.

**Shapes that carry this objective.** No shape in the picker defaults to this label, so the tag comes
from the discriminating test, never from the shape table. Pick the shape whose structure the sizing
already has and write the criteria arithmetic into the design note. task106 carries it on a shape
filed as "other" (a designation over every candidate with per-unit grids beside it).

There is no trap catalog for this objective under `../../../stumping/references/traps/`; read
`_cross-objective.md` there.

## The rule for reading them

**Never copy any example into a build. Not the scenario, not the entity, not the metric, not the
file names, not the wording of a single ask.** The examples show what a task in this objective can
be about and how a finished prompt reads. What every example shares, and what you take from it, is
the **shape of the decision**: a stakeholder with one call to make, a forcing event, and evidence
that pins exactly one answer down. Then draw a fresh domain, subdomain, entity and decision of your
own, and run it through the fingerprint guard (`../../../fingerprint/SKILL.md`) and the anti-clone
draw in `../../../stumping/SKILL.md` Part 6.1 before the ladder is written. A build that lifts any
scenario, wording or file name from the library is a clone, and the review reads it as one.
