# Stumping

> A stump is the analytical step a competent analyst skips because the default path looks finished
> without it: every figure is correct, every real rule filed, and the natural pipeline reconciles and
> commits to a specific wrong answer.

**The client's 10/10 rules bind every draw, rework and repair** (`CLAUDE.md`, first section): Part 1.1 answers
them in the design note before the default path is written. Work Part 6 first, then Parts 1 to 5, with `references/strategies.md`, the client's standard and rigor
patterns in `references/client/` (learn one, write your own; `references/client/measured-drivers.md` reads the
client's 49 measured tasks against our top-two bar: 18 held, 13 coin flips, 13 leaked their asks, 3 landed,
so a decisive rung is drawn from the held group, upstream of every graded figure, with its partial-fix match
counts in the note before any data is cut), `../guide-to-prompt/references/exemplars.md`
(the depth, never the withheld method) and `analytical_tasks/` seeds (a world, never a mechanism). The
portal is the only stump oracle; the leak reader and the judge's Gate F check the paper.

## Part 0. The goal and the opponent

The top two average under 50 per cent, one genuinely stumped; build to 40. A response on the call banks
about 45: the ladder keeps all but one off it, the asks hold the top two to a fifth of their weight
(`supplemental-stumping` Part 0). Builds fail when the call lands (Gate F), rigorous solvers disagree (A
to E), or the difficulty is a wrong number, a plant, a reading or a rule (G, H).

**The opponent** (79 rounds, 21 portal results) executes every clause, sees the schema, corrects by reflex
(holds the pool to every visible attribute, re-screens the residual, decomposes the pilot, builds the
analog, adds a control, reweights, shrinks), reconciles and back-tests everything, runs the hygiene
battery and the event study, and builds the default construction well (134 loop 0, four minutes). It never
asks what one row is, what population the decision funds when the file looks whole, whether a process the
window never saw generates the quantity, or which method a criterion selects when the obvious one fits:
difficulty lives there. The strongest model takes readings others decline (133 v1, 100 on the portal), so
screen, never assume.

## Part 1. Find the pitfall

### 1.1 The three rules, first and in writing

The client reviews every task against three rules and sends a break back even when the task is
deterministic and correct (`references/client/two-layer-task-design.md`, its good and bad prompts
included): the task really uses its domain; it has two layers, realistic mess and the analysis that
decides; a plant, data semantics or rule application may appear but never decides. They are answered
before the default path is written, in the design note's `## Three rules`, one labelled line per point of
the client's own check before a build ships. `precut.py` refuses a missing or one-word line.

| Label | The line answers |
|---|---|
| `Task type:` | the domain's task type the build sits closest to, one that serves the objective in the taxonomy (the guard and `precut.py` check it) |
| `Domain test:` | the quantity that decides the call and the field's own estimator, model or test for it |
| `Swap:` | the call sentence rewritten with another field's nouns, and what stops making sense |
| `Layer 1:` | each mess item and the system that produces it; nothing placed to be caught |
| `Layer 2:` | the family and the methodological choice that flips the call |
| `Decisive step:` | the analytical choice that flips the call, in the field's own words |
| `Not semantics:` | why reading every field, code, unit and definition correctly still leaves the easy route on the wrong answer |
| `Not rule application:` | which step no filed rule or procedure performs, so executing every stated rule still files the wrong answer |
| `Analyst test:` | the easy route a strong analyst takes with every field read and every rule applied, and the wrong answer it files (the default path's `Ends on:`, named) |
| `Estimand:` | the filed sentence fixing population, outcome, window, unit and comparison, and the file it sits in |
| `No decoy:` | that nothing is planted to be caught: no copied block, hidden rule, memo, draft, briefing or stakeholder figure written to carry the wrong answer |
| `No certified replay:` | that the method is not hidden and recovered by reproducing certified or published figures |
| `Lesson:` | what a model learns by getting it right, and why no build on file already teaches it |

**Rule 1, the domain.** A decision framing ("which clinics") is fine; the quantity that decides must be one
the field estimates, models or tests, worked the way its task type works it. Run the swap on the sentence,
never in the head: if the call still reads with a hospital for a school, or megawatt-hours for visits, the
domain is a backdrop and the draw is redone. A sort, filter, join, threshold or stated score deciding the
call is a backdrop at any depth (the client's bad pair: substations ranked by the grant rules' score). In
General Statistics & Data Science the setting is always another field's, so there the swap is of the
method: the deciding quantity is the task type's own statistical object (a distribution's shape, a model's
diagnostic, an interval's coverage), and replacing it with a generic summary must change the call.

**Rule 3, the decisive step.** **Litmus:** is the number the task overturns actually wrong, and is catching
that what defeats the model? Yes to both is a plant, banned at any depth. A field read, a unit converted
and a rule executed may sit on lower rungs and in the asks; the call never turns on one. The analyst test
(`analyst_test`) is the proof, and it is executed, not argued: `checks.py` runs the easy route on the
generator's clean truth with every filed rule applied and asserts it files the named wrong answer, then
changes the decisive step alone and asserts the golden (`dataset-generation` §7.1). A test that cannot be
written means redesign, never harden. Choosing the estimand or unit is analysis; the card's `stump_class`
is `analytical`.

### 1.2a Prefer a decisive step that picks among records-fixed answers

**Two checks on the graded object, before any method is run.** First, is the well-posed answer to "which
one" a name or a set? Where the records fix a set, a build that grades a name grades an arbitrary element
of it and no margin repairs that: task201's two-causal-variant branch had three of four licensed methods
agree on a tagger and none name the variant the design had designated. Second, an estimator's output may
be graded with its family closed to one form, and a name survives an open family only when the name and
the family are independent. **They are often coupled, and then the family closes only where the answer is
trivial.** task201 measured the coupling exactly: under a single-causal-variant model the causal variant
has the largest expected statistic because its correlation with itself is one, so the lead is the answer
and every method agrees; the only departures that move the answer off the lead, attenuation at the causal
variant and a second causal variant, are precisely what the licensed methods differ in handling, and each
split the family three to one on the graded name. So test the name across the family and across the
knob's range, and if the only settings where they agree are the settings where one sorted column gives the
answer, the ground cannot carry a records-fixed name.

**First, one line that decides whether the rest of this section is even the right question: is the filed
quantity observed in the records?** A decisive step that corrects a naive figure is one of exactly two
things. Either it estimates the same filed quantity better, and for two estimators of one quantity to
stand at all that quantity must be **unobserved**: a true rate, a future value, a causal effect, a latent
count, a counterfactual output. Or it computes a different quantity, and then filing that quantity is rule
application while not filing it is a fork on the main recommendation. There is no third position, which is
the WHAT screen's own wording reached from the other end. So where the filed quantity is a recorded
statistic the records fix it, nothing is left to estimate, and anything calling itself a correction is a
different quantity: the only live levers there are selection and nonlinearity in how the records relate to
it, and a records-fixed decisive step is available only in that case.

The test has predictive content, not just explanatory, which is why it leads. It gives 1.2's survivor list
exactly: regression to the mean in a unit chosen for standing worst files a true or future level, and the
staggered-adoption counterfactual files a causal effect, both unobserved and both survivors, while a ratio
of totals against a mean of ratios files a recorded statistic and fails, which is what task200 measured
from the other end. It also holds across every shipped driver on Anomaly Detection: a true density behind
grouped tests, a true count behind an instrument's labels, events only partly captured, an average over
values known only as bounds, an understated small-event count, a per-slot count the records never state
because they carry windows, an ultimate count still being coded, a counterfactual output at one second.
Every one files something unobserved, and no counterexample stands in the corpus. It also explains the
deaths: task198's architectures 2 and 3 both filed a recorded change and corrected its variance, so both
were computing a different quantity and both died.

The decisive step may decide a selection, a threshold crossing, a count of qualifying units or which of
several recorded quantities the comparison runs on, and then every graded figure is something the records
fix exactly. It may instead produce an estimate, and then every graded figure is an estimator's output and
has to survive every estimator the data does not close. Four architectures in one lane died on that second
shape: a residual identifiable only through a fit (task182 v3, the fourteen graded levels forked nine to
eighteen printed units), a length-bias correction (task182 v4, seven routes spread 7.8 to 14.4 points
against a printed unit of 0.1 to 1, and the easy route the best estimator at the realistic interval so the
ladder inverted), a fitted counterfactual whose two forms were collinear (task194 v1), and a conditional
expectation whose matching tolerance was a knob (task198 v1).

**An estimator's output may be graded, but only with its family closed to one form**, by a standard's own
definition (a pooled-sample maximum likelihood estimate, 188) or by the data's structure (which measured
rates transport outside the window they were measured in, 192). Closure is measured before any data is
cut, not argued: enumerate every form a competent analyst would use, compute the graded figure under each,
and require the spread inside 0.4 of the printed unit. **Watch for the single dial.** In both task182
deaths, ladder strength and licensed spread rose together with one parameter (the fit's output range, the
snapshot interval against the median duration), so re-tuning moved along the curve rather than off it. If
the two cannot be separated, the mechanism is spent.

### 1.2b The pincer on a break in the records, and the one case that lives

**Case two needs a statistic whose value is not invariant to the parameter being recovered, and that is
one computation rather than a judgement.** Having information "about its own production" is not the test:
something observable has to move when the parameter moves. The cases that hold pass it for that reason, two
vintages measuring a coding lag because the lag is exactly their difference, an audit subsample measuring
error rates because it is a second independent look at the same unit, shared specimens measuring dependence
because both screens see the one specimen. A multiplicative thinning of a count fails it, because every
observable (the count distribution, the repeat shares, the inter-event structure) moves only through the
product of rate and reporting. **Price it by profiling the likelihood of the claimed self-measurement over
the parameter to be recovered with the nuisance parameters free, and reading the width of the set within two
log-likelihood units.** A flat profile is case three whatever the mechanism's story sounds like. **And curvature is not a yes or no: read
the set's width against the printed precision, because a bounded profile can still be useless.** A thinned
count observed through event times does carry curvature, of order the process's regularity, and the set's
width falls only as the square root of that, so no realistic event stream supplies enough: task202 measured
the graded figure pinned to 0.46x to 4.50x the truth at an exponential process and still 0.86x to 1.06x at
an inter-arrival shape of 8 with 600 observed events, which is a markedly more regular process than any
incident stream, and reaching plus or minus 2 per cent would need a shape of order 200, a coefficient of
variation near 0.07, which is clockwork. task201's bounded profile failed the same way from the other
direction, its sharpest setting still twice the printed precision. So the shape to look for is not times as
well as counts, which is one view measured twice, but two structurally different views of the same events. task200's
dark-figure candidate passed every paper screen and died here: the profile over the reporting level was flat
from 0.10 to 1.00 within 0.08 log-likelihood units, so true incidence was pinned only to 38.0 to 367.3 per
1,000 households, about 8,200 times the printed precision, and state dependence did not rescue it because a
state-dependent thinned process is observationally equivalent to a sparser process with a different
dispersion and a different decay. The escapes all add a second non-invariant observable and each is spent or
banned: a second independent observation of the same events, an audit or verified subsample, a
complete-reporting sub-population whose rate transports, a filed external rate (rule application), or
selection on a recorded attribute rather than on the count, whose residue is where the complete region
starts and so is a cut-off.

A break in how the records were made (a system cutover, a basis change, a rename, an extract window, a
definitional change) decides the call only if the analyst gets it wrong, and there are three cases. **One:**
the pack states the break, so the right computation follows from reading a shipped sentence, which is data
semantics or rule application and banned as the decisive step. **Two:** the pack does not state it and the
break is a quantity the records measure about themselves, which is the only live case. **Three:** the pack
does not state it and it is not exactly measurable, so it is either recovered as an unstated rule, which is
banned, or unidentifiable, which means the design needs a field the pack does not have.

The distinction that decides which case a candidate is in: **a fact about how records were produced does
not measure itself, while a quantity the records measure about themselves does.** A cutover does not
measure its own capture difference, a basis change with no overlapping period measures nothing, a rename
measures nothing, an extract window measures nothing. Two vintages of one series do measure their own
coding lag (194), an audit subsample does measure a classifier's own error rates (192), and shared
specimens do measure the dependence between two screens (195). task198 screened fourteen mechanisms across
three routes and every one died in case one or case three, which is what sent the number to a new world.

### 1.2 The stump lives in HOW, never in WHAT

The estimand (population, outcome, window, unit, comparison) is filed so its literal execution is the
golden's quantity (`determinism-check` §1). The method stays open only when the design and the data's
structure (preferred), a standard's method or a filed selection criterion (an organ, never in consecutive
builds) force it. If the literal estimand makes the call easy, it was a fork.

**The WHAT screen, run at the draw.** Name the decisive step, then ask which part of the estimand it
settles. If it settles the population, the outcome, the window, the unit or the comparison, the draw is
dead and no hardening saves it: file that part and the computation follows from the clause, which is rule
application; leave it unfiled and the call is not determinate; there is no third position. Three
architectures died at stage 4 on this one shape, each with Gate G and Gate H passing and every figure
reproducing:

| Build | The decisive step | The part of the estimand it settled |
|---|---|---|
| 190 | decide to nowcast the caseload rather than count it | whether members not yet observed are in the population |
| 192 | count the processes behind the bursts, not the bursts | the unit of the count, which no parameter-free reading fixed |
| 193 | leave the one dominant product out of the comparison | the comparison population |

A step that survives the screen settles none of them: the estimand is beyond argument and two or more
methods of estimating that one filed quantity still stand, with the data's own structure ruling out the
easy one. Regression to the mean in a unit chosen for standing worst, the wrong counterfactual under
staggered adoption survive it, because each is a way of estimating a quantity the records already fix.
**A ratio of totals against a mean of ratios survives only under a condition worth stating, because it
usually fails.** Where the two differ by weighting alone, what separates them is the estimand's unit, and
the unit is one of the five parts: name it ("as a volume-weighted average") and the computation follows
from the clause, which is rule application and names the decisive quantity besides; leave it unnamed and
the readings of "averaged over the year" are three different numbers, which is a semantic fork on the main
recommendation and makes the stump a reading. task200 wrote the clause both ways and measured the unnamed
one at 12.22, 12.22 and 9.20 on one cut, and found no third position: a physical total is the named version
spelled differently, and treating the sources as a sample moves the separation onto the recorded sampling
design, which is filed and so semantics again. It survives only where the two are estimators of one
quantity under a design the pack does not fix, and a realistic pack records the design. The arithmetic is
not the problem: that instantiation cleared its boundary by 26.7 standard errors over 60 seeds, on the
right side in all 60, and died on the estimand sentence and on the swap test, where "each source already
carries its own mean and the volumes sit in a separate return" reads identically with branches and basket
values, or wards and bed-days, so the generating process has dropped out and the domain is a backdrop. The family label does not decide this:
`estimand_identification` holds both the survivors and the three deaths above, so a draw in it writes the
screen's answer into the note, naming the estimand's five parts and the sentence that files each, before
the default path is written.

### 1.3 Couple the pitfall to the domain

The decisive step is the field's own method for the deciding quantity, which an expert applies and a
generalist replaces with a generic move. Read the patterns, exemplars and family record first; the note
gives one line per source: what it teaches, how this build differs.

### 1.4 The four gaps, and the patterns with a record

Pick the gap, then the mechanism (`strategies.md` Part 4), then the scenario. **1 Time:** what the
evidence is about and what the decision bets on (`forecasting`). **2 Population:** what one row is, and
one decided unit (`method_or_model_selection`, `decomposition_attribution`). **3 Objective:** what the
decision is scored on (`binding_constraint`, `decomposition_attribution`); legal only when the metric is
correct and an unchecked constraint removes the pick re-placing nobody (58 v3, v4), never "their metric
misleads". **4 Rule:** which method a filed criterion the data settles selects (C2).

Each pattern fires only under its condition. **A** past exceedance against forward yield: candidates
resolve for an ordinary reason the series shows, a filed logistics fact pins the horizon, and no past
ranking ships as the answer. **C** serviceable share behind a join: an absolute share the analyst builds,
the winner's edge clearing the decoy's carried advantage, never a column or a stated eligibility rule. **D** two flawless grains: different in shape, the grain pinned
by what the decision funds, no key bridging them (44). **E** conditioned yield: an absolute split,
confounders controlled by construction, no column naming it (43). **B**, a recovered rule, never decides.

### 1.5 Write the default path first

First write the pipeline a competent analyst builds without thinking, from the prompt's words and the
files' grain: numbered steps naming files, joins, filters and construction, ending on a named figure. **If
it ends on the golden there is no stump** (134 loop 0, 130 v3, 100 v1). A rung that bites only a solver
who adds a correction is not a rung.

### 1.6 The stump sentence

One sentence: the wrong answer the default path files and the step that lands it there, naming the `Ends
on:` figure. `precut.py` refuses a default path ending on the golden or a sentence not naming it.

### 1.7 The data-native sentence

One line: what in this dataset (its generating process, grain, calendar, censoring, selection, identity or
capacity) makes this the stump an analyst trips on here. A move that reads the same anywhere is not built.

### 1.6a What survived, stated positively

Most of this skill records what kills a decisive step. One shape has passed a judge at Gate F strong, and
it is worth drawing from rather than rediscovering: **an unobserved quantity, identified by a construction
that combines two files at different grains, where the construction's own inputs are varied enough that no
sorted column and no clean subset reproduces it.** task197 files the output a unit would have produced had
the driving signal stayed inside its dead band, which nothing records; recovering it needs the programme
schedule (one grain) read against the high-resolution archive (another), and the ramp between setpoints has
to be fitted rather than looked up, from recordings that are a minority of an archive carrying five capture
kinds, 222 lengths and 97 offsets. Each clause of that sentence answers a screen: unobserved satisfies the
dichotomy; two grains means no one file publishes it; fitted means no subset reveals it; and varied inputs
mean the organ does not announce itself. Where a candidate is missing one of those clauses, that is the
screen it will die on.

## Part 2. Make it survive the opponent

### 2.1 The readability screen

Each rung runs six tests on paper; any that fires makes it readable, and a readable decisive rung is dead
(36 of 79 rounds, 13 of 21 portal results; `strategies.md` Part 6). **1 Filed sentence:** a clause,
definition or formula names the decisive quantity, or only makes the solver ask the question: a clause it
cannot avoid reading sends it looking, and a join forced by a key it already holds is one line of code; a
template asking for each candidate's affected population is that clause for every candidate (500 v2). **2 Schema:** a column, key or marker makes it a row
predicate or a header-found join. **3 Reflex:** an opponent default. **4 Control bench:** a control or
corpus scores the rules or refutes the naive read. **5 Hygiene:** the battery finds it (73 v2, 117). **6
Linear:** one subtraction, ratio or half of a reported figure. The note gives a row per rung, verdict
last, the decisive row `silent`. Shapes that held: every reflex lands wrong (181); the maturity attack
(the graded object crystallises after the extract, closed periods tie because developed, the tail sits in
a registry the natural pipeline never joins, no as-of dates; 73 world seven); a quantity believed to need
no construction (60 v4).

### 2.2 No semantic fork on the main recommendation

A term read two ways is a fork and data semantics at once; six builds carried one as their difficulty
(134: "booked again" against "return"). The `## Semantic fork table` (`determinism-check` §2) gives each
main-ask term and computation convention a row, every alternative ruled out by a quoted sentence or `same
call`. The stump is never a reading.

### 2.3 The deletion tests

Each kills a candidate decisive step. **1** Delete every wrong number and misleading claim: still hard, or
a surface-read rejection. **2** Clean data: the easy route on the clean truth still files the wrong answer,
executed in `checks.py` (`dataset-generation` §7.1). **3** Lens swap (`determinism-check` §4). **4** Identity: if
the governing arithmetic closes over shipped quantities, change the graded quantity (73 world six, 36).
**5** Control direction: each control is absent or ties under every basis for a reason true now at its
grain, the device netting to zero there (L1, L8). One refuting the naive read is a search bench (92 v2, 89
v5); one blind only until the forward window is the validated decoy the guard blocks. **6** First moves:
the one-period group-by, the pilot decomposition, each clause's natural reading, each corpus back-test,
the hygiene battery; any landing kills.

### 2.4 Oracles

List every control, published figure, reconciliation column and corpus with what it confirms on the
wrong path. One tying only under the golden is an oracle: cut it or make it tie on every basis. The ask
layer's referee never arbitrates the call.

## Part 3. The ladder

Three to five rungs, four by default, each a defensible analysis climbed by refusing it: rung 0 the
default path, 1 the obvious correction, 2 the sophisticated one, 3 the silent decisive move (two fall to
one correction, six read as ambiguity). **Rung 0 is never shipped:** no artifact ranks the candidates
wrongly, at any depth, except a declared wrong-basis distractor (`dataset-generation` §8.3); a dimension
table the naive pipeline needs is rung 0 (42). **Every rung** reproduces from the raw files, names its own
candidate, dies to exactly one shipped fact or construction, and is satisfying to stop at; a loop-fixable
slip (58 v5) or one group-by (36) is no rung. Cleaning sits at rung 1 or 2. Depth is a Gate F device,
never a Gate G defence. **Read rung 0 off what the shipped files name, free text included:** remarks naming
the counterparty each affected case waited on hand that candidate to the natural pipeline whatever code sits
beside it, and the one entity present only in the later period is the first thing a two-period comparison
lists (500 v1). **Measure the decisive rung on the graded name and the graded figure separately:** a rung that
only changes who is blamed, while the counterfactual figure is the same whoever is blamed, is worth nothing on
the figure, and a response skipping it files the golden figure (500 v1).

**Price the estimator's own standard error in the same breath, in the graded figure's units.** The ceiling
test is necessary and not sufficient: a decisive step whose estimator's standard error exceeds the ladder's
margin cannot rank, however large the bias it chases. task198's architecture 2 priced 9.4 points of
available bias against 4.5 needed, with the two separations financed by independent parameters, and died
anyway, because the step had to recover a per-interviewer differential and the record measures it only
through that interviewer's own out-of-unit workload: 33 observations at a median field load, a standard
error of 6.96 points against a golden rise of 3.0, so the correction injects several times more noise than
the bias it removes and lands on whichever small unit drew unluckily (the golden named in 2 of 12 seeds).
A one-point standard error there needed 1,600 observations per interviewer per quarter against a realistic
50 to 80, and noise falls as the square root, so no feasible pack closes it. **Prefer a decisive quantity
the whole population estimates** (a variance component, a rate over every unit) **over one estimated
per unit from that unit's own thin slice.** And watch for the dial that fails at both ends: there, a
persistent differential made the additive control a solver reaches for the right analysis, so the schema
tell reached the golden, while a non-persistent one left the within-period estimator too noisy to rank, and
no setting satisfied both.

**A decisive step that moves a variance cannot carry a ranking**, because the variance that reorders the
candidates is the variance that randomises the quantity they are ranked on: the lever and the noise are one
number, so the dial fails at both ends and the two ends are the same end. Compute the lever's size in the
ranked quantity's denominator and that same quantity's contribution to the numerator's spread, and if they
are one variance the step cannot rank. task198's architecture 2 ranked units on a change over its spread,
where the spread is `sigma_b sqrt(HHI_cur + HHI_cmp)`: the two-interviewer unit at a workload concentration
of 0.642 carries 1.13 `sigma_b` against the fourteen-interviewer unit's 0.38, a ratio of three whatever
`sigma_b` is, which is exactly what flips the ranking, and that same spread is the random swing in the
measured change (intended rises of 0.4 to 5.5 points against realised changes of +17.1 to -17.2, the golden
named in 2 of 14 seeds). Large enough to flip is large enough to randomise, and shrinking `sigma_b`
stabilises the numerator and removes the lever in one stroke, so no feasible pack closes it. This is not a
Gate C finding: on any one cut pack the analysis gives one answer and the estimator family is closed. It is
a failure to be buildable to specification, because the rungs, the margins and the loud and golden roles
would all be hostage to the seed. **Judge-against-noise mechanisms stay sound where the answer is a verdict
on one named candidate, or a flag against a stated threshold on a given pack; they cannot decide which of N
is largest.** Reaching the verdict shape is also the repair: task198's architecture 3 keeps the same world,
pack and variance component and moves the decision from a pick of one region to a characterisation of one
named region's move, which puts the whole lever on a threshold the pack is cut against.

**What actually decides it is the distance to the decision boundary in units of the lever's own noise, so
measure that number rather than preferring a shape.** A ranking of N has N minus 1 boundaries and the
nearest is usually close, which is why rankings nearly always fail; a verdict has one boundary and can be
placed far from it, which is why verdicts usually survive. Usually is not a licence. task198's
architecture 3 put the flip 61 per cent of the variance component away, about fifteen relative standard
errors and four hundred times the estimator family's own spread, and holds. task200's first direction was
a banded verdict on one named facility and died anyway: the lever was a measurement variance removed from
an observed variance, the graded figure's noise was the sampling error of those same two variances, and
over 40 seeds the golden ran 1.108 to 2.161 mg/L against a truth of 1.471 and a band edge at 2.000, so the
golden's own tier took both values. Under one standard error to the boundary is seed-hostage whatever the
decision's shape. Two further numbers from that screen are worth carrying: eleven estimator forms a
competent analyst would use spread 0.52 mg/L on average against 0.04 permitted at the printed precision,
over by about thirteen times, and the forms all agreed on the tier within any one seed, so only the
across-seed run exposed it. And where a variance lever is taken at all, take it on a percentile rather
than on a tail share: the percentile's lever is linear in sigma while a tail probability's noise blows up,
which on that ground was 7 standard errors against under 1 for the same idea.

**A variance-correcting step cannot be silent on a call about a change while the unit's own history is in
the pack**, because the component that makes the supplied interval wrong is the component that makes the
history wobble. The two are the same number from both sides: a differential redrawn each period inflates
the variance of a change and is readable off the series, while a persistent one is invisible in the series
and cancels out of the difference entirely, so there is no setting at which the correction matters and the
series does not show it. task198's architecture 3 died on it after ten listed reflexes all landed wrong at
z 2.95 to 4.60: the eleventh, judging the rise against the region's own quarter-to-quarter variation, gave
five consecutive changes with a standard deviation of 9.15 points against a 7.64 rise, so z 0.83 and the
golden verdict in 5 of 5 working seeds, with no component, no workload log and no re-formed replication
anywhere in the route. Consolidating the panel left the history's own change spread at 9.06 and broke rung
2 instead. Sound only where the unit has no usable history in the pack, or where the call is about a level
rather than a change. One computation prices it: take the unit's own period-to-period standard deviation
and the correct standard error, and if the first is within about a factor of two of the second, the
decisive rung is readable off the series.

**The reflex sweep is only as good as the enumeration behind it,** which is why it is run as code and why
the enumeration is written down and argued rather than listed from memory. Ten reflexes landing wrong is
evidence about those ten. Enumerate by asking what the decisive quantity is a substitute for, then list
every other way the pack measures that same thing: there the correct spread of a change had an empirical
twin sitting in the unit's own series, and nothing in a sweep of corrections, poolings, stratifications
and shrinkages reaches it.

**When the decisive quantity is recovered exactly from a subset of the records, ask what else that subset
hands over, because a mechanic that distorts some rows usually publishes the truth on the others.**
Censoring, capping, flooring, truncation and suppression all split a file into rows the mechanic bent and
rows where it bound exactly, and on the second set the hidden quantity is printed rather than estimated.
task198's architecture 4 priced a lesser-of payment rule: on an uncensored line the payment understates
the contracted rate, which is the bias the decisive step corrects, but on a censored line the payment
**equals** the rate exactly, by the same mechanic. So the group whose contract bound on 38 per cent of its
lines published its own rate in full, and a filter-and-divide over censored lines returned 433.283 against
the decisive route's 433.283, the answer rather than an approximation. Sparseness is no defence when the
recovered quantity is constant: one revealing row is enough. And the exactness cuts both ways, which is
the trade to price: what made that step's estimator standard error 0.0000 per cent is what made the easy
recovery exact, so the two cannot be separated by tuning, and driving the revelation to zero hides the
quantity from the decisive route as well. Here censoring is revelation. **The same screen closes a whole identification family: "estimate the nuisance where the signal
vanishes" fails it by construction.** The region where the signal vanishes is a subset that publishes the
nuisance, and the leverage that makes the identification sharp is exactly what makes that subset pure, so
one dial controls both failures and there is no setting between them. task201 measured four settings of a
regression-on-a-covariate identification: widened, the regression pinned the nuisance to twice the printed
precision and the low-covariate bin alone named the answer; narrowed, the low bin was contaminated enough
to name the wrong candidate and the profile ballooned to ten times the printed precision. Three of the nine
enumerated routes reached the golden and all three were the same move, reading the region where the signal
is absent. This closes every identification whose nuisance is an intercept recovered from a null region:
a regression on a covariate that vanishes, negative-control regions, calibration nulls, blank-sample
baselines. One computation prices it before drawing: compute the nuisance from the lowest bin of the
covariate alone and see which candidate it names.

Beware also the complement: the
share of rows the mechanic bound is itself a ranking signal, and there six groups sat at 99.6 to 99.8 per
cent censored while only the two dearest contracts sat near 38, so sorting on "whose rule binds least
often" flagged the answer set outright.

**The pricing sequence, run in this order before a word of design:** name the residue the filed WHAT leaves
(a knob fails at once, only a method survives); price the move available against the move needed; price the
standard error of whatever the step must estimate; check whether the lever and the ranked quantity's noise
are the same variance; where the step corrects a variance on a call about a change, check whether the
unit's own history already estimates what the step computes; and where the quantity is recoverable exactly
from a subset of rows, check what that subset hands over. Each is one computation on the clean truth and
each has killed a family that paragraphs of argument had left open.

**Price the move against the ceiling before screening a candidate at all.** Compute two numbers: the points
the call has to move for the candidate to decide anything, and the largest move the affected population
could produce if every one of its records flipped. task198's cutover family needed 8.79 points and could
produce at most 2.644 on any queue, so one computation killed a whole family that three paragraphs of
argument had left open. Run it first, on the clean truth, before any screen that costs design time.

**Two separations financed by one quantity are priced together, before the design is accepted.** A ladder
usually needs two inequalities to hold at once: the easy route must lose on the record as it stands, and the
answer must win once the decisive step is taken. When one quantity pays for both (the uplift a correction
carries, the drift a restatement carries, the lag a vintage carries), they trade off directly, and buying
one spends the other. Compute the budget in the graded figure's own units, compute what each separation
costs, and check the sum before any data is cut: task194's architecture 3 had a 27.25-complication budget,
spent 18.38 of it on a 2.35 flip and a 16.03 margin, and clearing both comfortably would have taken 33.14,
so the point that cleared the margin left the flip at a third of a standard error. Scale is rarely the
answer, because the budget grows with the count while its noise grows with the square root, so closing a
shortfall of that size means an entity several times the size of the one the decision is about.

**The arithmetic, on paper before any row.** Position, margin, separation and dominance as
`dataset-generation` §6 asserts them (4th or 5th on rung 0, no margin under 1.15x). Then: one live degree
of freedom in the graded quantity holds no ladder (49); the decisive move is never the smallest (37);
every correction walks one way and only the decisive move reverses; a quantile absorbs a selection rung
(44) and a share cancels one moving both terms, while totals, counts and levels carry rungs, so each
rung's worth is computed on the graded quantity, never an intermediate; every grid cell is a named wrong
answer or outside the floor, n monotone corrections at f needing a reversing g >= 1/((1 - floor) f^n),
partial applications swept, hazards adding path length but no cell, the answer extreme or bracketed (L3 to
L5, C4); every single-error cell files a feasible figure (44); and a saturated grid takes no rung, while
cutting one can buy separation (45).

Stack two to four mechanisms from different gaps, the decisive gap not rung 1's; same-pattern stacking is
one mechanism twice. **A hold** (`signal_vs_noise_or_hold`) is determinate when a computed blocking
quantity reproduces, every candidate fails for a named reason, the prompt licenses a non-pick on equal
footing without advertising it, the default path still names a candidate, and the note says what would
have made a pick. "The data is unclear" is a hedge.

## Part 4. Force one answer

`determinism-check` owns it. HOW is forced, and a filed method is rule application (§1). The
literal-reader test (§2) runs on the ladder before data is cut. No filed rule, basis or formula reads to
another answer (an official decoy). **A pin fixes the basis, never the answer:** if the answer stays
forced with the clause deleted, it handed over the insight (57 v21); it names the observable, never a
file, field, join or the move, sits once at authority, never in the prompt, and is re-screened. Converge
first (C1). Figures sit mid-bin on non-round values (100) with a stated flip condition, no money on a
half-cent. The call is forward facing by default; a retrospective one carries its reason.

## Part 6. The draw: a unique stump

A stump recognisable by its shape has lost; a template is sent back however far apart the surfaces are.
**The card:** `guard.py recent` and `coverage`; draw every card axis independently (the objective from the
graded quantity's tense, people from `guard.py names`); check `corr(decisive measure, unit size)` at the
decision grain (57 died, +0.98); `guard.py check`, BLOCKs cleared and WARNs answered; `register` before
the ladder.

**Where a fresh stump comes from.**
- **The field's estimator meets the data's process.** List the field's methods for the deciding quantity
  and the generic move a generalist makes instead; then write how each file's rows come to exist (who
  records them, when, by which route, what they cannot see). Pitfalls live where recording differs from
  the event: delay by route, reporters not yet filed, checks that see a unit just before resetting it,
  replacements restarting a wear curve, detection falling as targets grow rare, sub-units sharing a
  budget, a lagged response to a shared driver, a yield moving with the base rate while error rates hold,
  competing exits left in a base, a hazard by time since entry.
- **A latent structure no column names:** the conditioning variable that makes the pooled quantity wrong
  (route, reporter, household, entry date, pool mix), rebuilt from a history, a join or a grouping.
- **Every reflex lands wrong:** list the reflexes for this pitfall (pool, aggregate scale, stratify on
  visible attributes, trend, reweight, shrink, add a control); each files the default or another named
  wrong answer (181, 445, 446, 230). A reflex reaching the golden spends the stump.
  **Run the sweep as code before the ladder's numbers are measured, not after.** The sweep is cheap, about
  a minute on a cut pack, and it decides whether the mechanism can carry a ladder at all, so measuring
  separations first spends the design time twice: task194's architecture 3 had every filed floor cleared,
  1.50x on rung 0 and 2.008x on the decisive rung, and died anyway because 6 of 22 reflexes reached the
  golden, the worst at 3.47x.
  **Orthogonality is a construction, not a check.** With the 9 to 16 units a slate-valued call carries, a
  driver drawn independently of the visible attributes still correlates with one of them up to about 0.75
  by chance: task182's first model hit +0.751 against night share on its first draw. Residualise the
  driver against every visible attribute at draw time, which holds the maximum absolute correlation at
  0.000, and then assert it. Drawing independently and testing afterwards costs a redraw every few seeds.
  **And a slate needs as many real effects as it has places.** An internally standardised score puts every
  non-anomalous unit at exactly 1.00, so a slate of k has its boundary inside the noise unless k units
  carry a real effect; task182's first sweep failed on that before its realism problem even appeared.
  **What makes a reflex reach it is a correlation the designer put there.** If the thing that creates the
  signal also predicts the outcome's level, a finer standardisation gets the answer for free: there the
  lag's depth followed the complication groups, those groups come from old, comorbid, long-staying
  patients, and those are exactly the patients the published standard under-adjusts for, so holding the
  pool to every visible attribute arrived at the golden with no maturity analysis at all. So the signal's
  driver is chosen orthogonal to everything that predicts the outcome, the association between the two
  measured and asserted near zero, and no single visible grouping (a site, a specialty, a vintage flag)
  may isolate the rows it acts on. Where the signal lives only in the time structure, no cross-sectional
  control can remove it, which is the property to engineer for.
- **Wrong now:** the default construction is wrong on the data in hand; a record blessing the naive method
  until the window breaks it (27 of 30 builds) is blocked.
- **Under-used ground first:** `uncertainty_hold` was never drawn, `causal_design` and
  `identity_resolution` never held, the emerging habits beat the top four. Pick the strategy, then data.

**Test it against the cards and the record.**
- **Read the mechanisms on file first:** `guard.py mechanisms --objective <o>` (and `--gate-g <g>`) prints
  every driver and earlier architecture on that ground in one screen; write one line on the insight each
  spends and draw from what they leave. The driver score misses a mechanism told in other nouns: two task500
  re-roots passed `check` at 0.05 and 0.08 and still repeated 109's and 111 v1's drivers.
- **Abstraction test:** strip the nouns from your driver and the three `guard.py nearest` returns; one
  that maps onto yours (the same latent structure, default path and correction) is the same driver at any
  similarity. Change the structure, never the nouns; read their `## Tried and rejected`.
- **Same-puzzle test**, answered in the note: gap, decisive pattern (or G-code) and decision type equal to
  a build in the last twelve, lineage included, is the same puzzle; gap, pattern and Gate G mechanism
  equal is the same driver (86 v1 against 72 v2). Redraw the gap or the pattern; a new world fixes
  neither. An older match needs a one-line differentiation.
- **Standing bans** (`fingerprint`): every card axis from the pairing to the people against the last three
  builds, the shape against two, a Layer 2 pattern on the same data structure ever; driver text blocks at
  0.30 similarity and warns at 0.12.
- **The record:** nothing drawn is dead (`strategies.md` Part 6, `shipped-ledger.md`), the pattern's
  discriminator (1.4) can be built here, and a re-root moves the decisive rung.

**No monoculture.** The guard blocks a strategy within three builds and warns at three in twelve: rotate
the strategy, Layer 2 family and gap across the batch. The semantics-risk strategies (`time_semantics`,
`grain_or_unit`, `identity_resolution`, `stated_rule_hard_construction`, `withheld_rule_corpus_fit`) warn;
their `analyst_test` names the easy route that still fails. **Re-skin devices, never drivers:** a twin
pair, an absolute split, a free training instance, complete-partition invariance or silent mess is reused
freely; the insight carrying the stump never is, and two drivers that read as one insight without their
nouns are a clone.

## Part 7. The organs, only where the strategy needs them

**The pin:** one filed sentence at authority naming the observable (Part 4). **The confirming corpus,**
only for a forecast chosen by honest back-test or a filed criterion shown to select one method, under C2
(`forcing-the-answer` Part 2); it never recovers a rule, refutes the naive read or blesses the wrong
method, and every outcome in it reproduces. A twin pair kills a lookup (O1). **Distractors:** two or more
files the solution never reads that look worth weighing, named only in `metadata.json`, never the stump.
**Voices:** optional, at most two people with beliefs, never a roll call or a quoted ranking; a rival
method arrives as the shortcut, never a document filed to be refuted. **Context artifacts** never rank the
candidates. No organ ships because earlier builds shipped one.

## Part 8. Diagnosis and repair

A diagnosis comes from the judge or the portal, never a solve in the main thread; returned tasks take
`/fix-determinism`, `/fix-rubric`, or stage 2 when the call landed (`build-pipeline`, Returned tasks). Diff each response against the golden cell by cell: the step it never took
is the finding, and an assumption every response holds unchecked is where to change the world.

- Landed on the default construction: make it wrong, a rung below rung 0 from another gap.
- Executed the decisive step as a work order: move it off every sentence and column, or re-root if only a
  plant stays silent. Named the quantity and argued it away: file the criterion, never the method.
- Reached every insight and defended another answer from a file, or read a term two ways: a fork; add the
  `SF` row and converge (`determinism-check` §2). An undesigned wrong candidate: close that reading.
- The last rung never moves the ranking: widen the edge or shrink the carried advantage. A control quoted
  back: tie it under every basis, or cut it. Missed the call yet scored high: rebuild the asks. The name
  right, figures wrong, repeatedly: re-root so the name is not graded. "The figure looks wrong": Gate G;
  rebuild, never harden.

**Harden, in order:** a rung from another gap below the decisive one; the discriminator behind a join; the
pin's evidence split across two documents; the winner's default-path rank worse; a conditioned yield; the
corpus tightened. **Never** noise, removed evidence, an invented threshold, harder parsing, a wrong-answer
artifact, or a deleted signpost that carried a parameter. **Stop rules,** written before the first portal
test: two exact solves by different routes re-root the ask; two determinism repairs that each made their
rung a reading re-root the difficulty; repeated solves change the decision, not the mechanism. One
mechanism per repair, a rule with the records that reproduce it, the dead end written when it dies.
