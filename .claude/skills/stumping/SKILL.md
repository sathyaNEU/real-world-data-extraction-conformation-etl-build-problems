# Stumping

> A stump is the analytical step a competent analyst skips because the default path looks finished
> without it: every figure is correct, every real rule filed, and the natural pipeline reconciles and
> commits to a specific wrong answer.

**The client's 10/10 rules bind every draw, rework and repair** (`CLAUDE.md`, first section): Part 1.1 answers
them in the design note before the default path is written. Work Part 6 first, then Parts 1 to 5, with `references/strategies.md`, the client's standard and rigor
patterns in `references/client/` (learn one, write your own; `references/client/measured-drivers.md` reads the
client's 49 measured tasks against our top-two bar: 18 held, 13 coin flips, 13 leaked their asks, 3 landed,
so a decisive rung is drawn from the held group, upstream of every graded figure, with its partial-fix match
counts in the note before any data is cut), `../guide-to-prompt/references/exemplars.md`
(the depth, never the withheld method) and `analytical_tasks/` seeds (a world, never a mechanism). The
portal is the only stump oracle; the leak reader and the judge's Gate F check the paper.

## Part 0. The goal and the opponent

The top two average under 50 per cent, one genuinely stumped; build to 40. A response on the call banks
about 45: the ladder keeps all but one off it, the asks hold the top two to a fifth of their weight
(`supplemental-stumping` Part 0). Builds fail when the call lands (Gate F), rigorous solvers disagree (A
to E), or the difficulty is a wrong number, a plant, a reading or a rule (G, H).

**The opponent** (79 rounds, 21 portal results) executes every clause, sees the schema, corrects by reflex
(holds the pool to every visible attribute, re-screens the residual, decomposes the pilot, builds the
analog, adds a control, reweights, shrinks), reconciles and back-tests everything, runs the hygiene
battery and the event study, and builds the default construction well (134 loop 0, four minutes). It never
asks what one row is, what population the decision funds when the file looks whole, whether a process the
window never saw generates the quantity, or which method a criterion selects when the obvious one fits:
difficulty lives there. The strongest model takes readings others decline (133 v1, 100 on the portal), so
screen, never assume.

**A Gate F verdict from ONE reader landing the call has measured the design working, not a failure.** Part 0
requires the ladder to keep all but one response off the call, so the cracker landing it is the intended
outcome and two landing it is the ladder failure. An in-house audit ran a single reader against thirteen
builds, saw the call land, and wrote "Gate F failed" on each; that reasoning cannot distinguish the designed
single lander from a ladder failure. Those verdicts happened to be right, but only because clean-truth screens
separately showed MULTIPLE cheap routes landing each call (on one build, five one-group-by routes, one of them
a partition of the default path's own column), and multiple cheap routes is what implies both top responses
land it. **So judge Gate F on the count of cheap routes that reach the call, measured on the clean truth, or
on two readers; never on one reader's landing.** The same audit also handed its reader the figure KEY NAMES
from `figures.json` on at least one build, which its own leak line records: an audit harness is a shipped
artifact for this purpose and gets the same leak discipline as the pack.

## Part 1. Find the pitfall

### 1.1 The three rules, first and in writing

The client reviews every task against three rules and sends a break back even when the task is
deterministic and correct (`references/client/two-layer-task-design.md`, its good and bad prompts
included): the task really uses its domain; it has two layers, realistic mess and the analysis that
decides; a plant, data semantics or rule application may appear but never decides. They are answered
before the default path is written, in the design note's `## Three rules`, one labelled line per point of
the client's own check before a build ships. `precut.py` refuses a missing or one-word line.

| Label | The line answers |
|---|---|
| `Task type:` | the domain's task type the build sits closest to, one that serves the objective in the taxonomy (the guard and `precut.py` check it) |
| `Domain test:` | the quantity that decides the call and the field's own estimator, model or test for it |
| `Swap:` | the call sentence rewritten with another field's nouns, and what stops making sense |
| `Layer 1:` | each mess item and the system that produces it; nothing placed to be caught |
| `Layer 2:` | the family and the methodological choice that flips the call |
| `Decisive step:` | the analytical choice that flips the call, in the field's own words |
| `Not semantics:` | why reading every field, code, unit and definition correctly still leaves the easy route on the wrong answer |
| `Not rule application:` | which step no filed rule or procedure performs, so executing every stated rule still files the wrong answer, **and the measured spread of the estimator family the rule leaves open** (see below: a line that answers only the first half is worth nothing) |
| `Analyst test:` | the easy route a strong analyst takes with every field read and every rule applied, and the wrong answer it files (the default path's `Ends on:`, named) |
| `Estimand:` | the filed sentence fixing population, outcome, window, unit and comparison, and the file it sits in |
| `No decoy:` | that nothing is planted to be caught: no copied block, hidden rule, memo, draft, briefing or stakeholder figure written to carry the wrong answer |
| `No certified replay:` | that the method is not hidden and recovered by reproducing certified or published figures |
| `Lesson:` | what a model learns by getting it right, and why no build on file already teaches it |

**Rule 1, the domain.** A decision framing ("which clinics") is fine; the quantity that decides must be one
the field estimates, models or tests, worked the way its task type works it. Run the swap on the sentence,
never in the head: if the call still reads with a hospital for a school, or megawatt-hours for visits, the
domain is a backdrop and the draw is redone. A sort, filter, join, threshold or stated score deciding the
call is a backdrop at any depth (the client's bad pair: substations ranked by the grant rules' score). In
General Statistics & Data Science the setting is always another field's, so there the swap is of the
method: the deciding quantity is the task type's own statistical object (a distribution's shape, a model's
diagnostic, an interval's coverage), and replacing it with a generic summary must change the call.

**The `Not rule application:` line carries a number, and without it the line is worthless.** It is routinely
answered against the wrong question. "Does a filed rule name the method?" is not the test; **"is anything left
to decide once every filed rule is read?" is.** Three builds answered the first truthfully and shipped, and all
three were landed by a blind reader at medium effort:
- one filed the basis of a conversion and left ten admissible per-reading estimators that agree to **a spread of
  exactly zero** on the graded figure;
- one filed a confidence level over a quantity whose records fix every input, so only the variance was open, and
  **6 of 12 textbook routes file the golden**, two of them needing no insight into the design;
- one filed a counterfactual's definition, and its whole licensed family (4 of 4 constructions, 20 of 20 redraws)
  refers the committed set at **1.00 distinct designated sets**.

So the line states the family the rule leaves open and the spread that family returns on the graded figure. **A
spread of zero means the step is a reflex, whatever the documents say**, and the build is drawn elsewhere. That
measurement costs a minute on the clean truth and would have failed all three at stage 2 rather than at an audit.

**The line carries three numbers, not one, because "the family" is two different families.** A build can quote
the flattering one and look alive. The **enumerated** family is every construction a competent analyst would
reach for; the **standing** family is the subset the data and the filed rules leave defensible. One build
measured 9.17 printed units across its enumerated family and **0.68 of one printed unit, filing a single call,
across the nine constructions that actually hold the filed error rate**: alive on the first number and a reflex
on the second. Another measured 9.2 printed units enumerated and **exactly zero on six of its seven graded
figures** once restricted to the constructions that hold the filed false-discovery rate, with 12 of 13 filing
the golden. So the line gives the enumerated spread, the standing spread, **and the loudness of whatever does
the ruling-out**, because that third number is what turns the step into a reflex: if a filed clause or a
one-group-by comparison eliminates everything but one construction, the step is that elimination and not the
construction.

**Where the decisive step is the scale a one-dimensional per-unit statistic is read against, Gates C and F
cannot both hold, and that is algebra rather than a tuning accident.** Licensed constructions of a scale (a
null, a reference distribution, a benchmark spread, a robust location and dispersion) differ only in the
location and spread they divide the statistic by, so they agree on the answer set exactly when no admissible
scale reorders the units, which is exactly when one sort on the statistic is the answer. Unanimity and
one-column separability are the same number in both directions. Measured on one build at Spearman +0.8837
between how many crude routes land the call and how many licensed constructions agree, over 16 settings of
three independent dials, with **0 of 16 cells passing both gates**. The screen is one line at the draw:
compute the per-unit statistic, sort it, and ask whether the golden's answer set is an interval of that sort.
If it is, the step is arithmetic, and the build's own hardening assertion will say so, because "the found
units clear every other unit by X" is the statement that one sort is the answer.

**The dial is one-ended only where the easy route is itself a member of the licensed family, and that
condition decides which cell you are hunting.** This is the hinge the next two paragraphs turn on and it is
easy to lose. Where the decisive step **is** a choice among estimators, the easy route is one of the family's
own members, so making the family agree makes the easy route agree too: separation plus unanimity is then the
cell that **kills** the build, and the dial is one-ended. Where the easy route sits **outside** the family
because the data refutes it, which is the case whenever the decisive step is recognising that the record is
incomplete rather than picking an estimator, separation plus unanimity is the cell the build **wants**, and a
joint cell can exist. One build measured exactly that: six constructions filing one printed call, no wrong-rung
cell inside the alarm band, worst rung clearance 1.219 and the golden's cells at 1.857 and 1.717, with every
ladder floor asserted. Its dial passed, and it refused on a different screen. So ask first whether the easy
route is in the family; the answer flips which cell you are looking for, and a screen written without it
reports a passing build as a refusal or the reverse.

**The convergence Gate C rests on is the reach Gate F pays, so they are one dial.** (This paragraph and the two
after it hold where the condition above does: the easy route is a member of the licensed family.) A build whose decisive
step is an estimator choice has to make the licensed family agree, or the main call forks and the judge returns
`underspecified_objective`. Agreement is exactly what makes the step a reflex. Measured on one build as a dial
with both ends read: over 20 redraws of its world, 17 had a real separation and a unanimous family (nothing
methodological decided the call, and the blind reader took it), 3 had a split family and the separation had
collapsed to a lever-over-ceiling of 0.11 and 0.13. **No setting existed where the choice both mattered and was
determinate**, and the build's own `## Tried and rejected` recorded adding sites to the winner so every variant
sat in one bin, which is the trade written down as it was made. Six stage-2 repairs on six unrelated grounds
refused on this, every one measuring a family spread of zero on the graded figure. So an estimator choice is not
a decisive step on its own: what carries a stump is a step the data makes **necessary and unique** (the
population the decision funds, the structure a pooled quantity hides, the quantity no file holds), where the
family that skips it lands somewhere else and the family that takes it has nothing left to choose. Screen the
dial before the draw: if closing Gate C would make the family unanimous, the ground is spent.

**Assert the fork table's rows as a cross product, never one row at a time.** Two rows that are each a
licensed reading of the main computation can agree separately and fork together, because asserting one with
the other held at its golden value tests neither. One build asserted its pair definition and its pooling rule
one at a time, each green, and their 35-cell product forks the call **32 cells to 3**: any pair with an
aircraft changing level, fitted per sector rather than pooled, names no sector at all. Where two rows are
both live readings of the deciding quantity, the assertion runs on the product.

**Count the family wide enough that its members are not one method wearing three hats, and count groupings
as members.** A family measured over rival *placements* of one estimator is not the family: the member that
forks a build is as often a different **grouping** of the same estimator as a different penalisation of it.
One build measured the record refuting four rival placements at likelihood ratios of 3,035.2 to 13,660.0 and
shipped on that, and its judge then fitted the same estimator **per class** instead of pooled and got a
different committed answer: 7 of 8 named parts in common and a different eighth, the graded total 4,866
against 5,705, on a likelihood ratio of 511.1 on 668 degrees of freedom (z = -4.29), so the data neither
reject the pooling nor prefer it. The deeper reading is that a grouping the data cannot reject is the hardest
member to see, because the groups genuinely share the quantity and the rival therefore differs from the
golden only by estimation noise: the test is not whether the data prefer the grouping but whether the
decision's own margin clears the noise the grouping adds. Five times the parameters on the same rows raises
the variance rather than sharing it, so a margin sized against the pooled estimator's standard error is
sized against the wrong number.

**Count the family wide enough that its members are not one method wearing three hats.** The spread is measured
over constructions that differ in what they *do*, not in how they are penalised. One build asserted maximum
likelihood, Firth and Jeffreys agreeing within 0.0633 and called the method forced; those are three score
modifications of a single likelihood and agree by construction. The members that actually forked its printed
figure by 3.5 of its own units were the posterior summaries, the closed form, the Poisson route and the
size-stratified recombination, and none was ever tested, so an open Gate C rode through three judge passes
inside a passing assertion. The same defect for conditioning sits in 1.2; it holds for penalisation,
parameterisation and prior alike. A family of score variants, or of one estimator at several tuning constants,
measures nothing.

**Price the cheapest construction, not the one the design intends.** The algebra clause in 1.6a is run on the
*cheapest* licensed member of the decisive family, because that is the one a solver reaches. Measured three ways
on three unrelated grounds: a blend-unmixing step was **affine** in its forcing column, so one regression on that
column beat the designed estimator (0.0026 against 0.0028 mean absolute error); a premium was **linear** in the
day count its step moved, at 34 and 73 cents a day, capping every lever at 2 to 3 per cent; and an ordering
expectation equalled `n` times (the window's end less the other side's mean date) over the window's length to
**8.5e-14**, so the decisive construction was one group-by, one subtraction and one divide. In all three the
design's own readability screen had scored the decisive rung as not linear, and in all three the screen was
wrong by arithmetic. **Write the one-group-by route to the call in one line before the first harness, and do the
algebra on it.**

**Score the easy route as the cheapest LICENSED member of the family, never as the crudest route available,
because where identification is the decisive step those are the same column.** One pass screened a
linear-solve construction and reported a joint cell of 60.0 per cent by scoring the reflex as a pro-rata
apportionment at 36.0 per cent. But the cheapest member of its own licensed family is one call to a least
squares routine on the shipped exposure matrix, and that member's hit rate is the **99.0 per cent the
determinacy screen was reporting as a pass**. The same number was a Gate C pass and a Gate F failure at
once: where the decisive step is whether the sub-unit values are identified at all, the construction that
exploits the identification is one line, so family unanimity IS the easy route landing. **Print the cheapest
licensed member's own hit rate in the same table as the family's unanimity**, every time.

**The shape that shipped, and why it is SPENT AS A DRIVER rather than a shape to draw.** A rule or change
applies to one unit while the organisation reports another, and the effect propagates through a structure
that organisation's own process imposes (a rotating panel, a cohort, a cycle, a vintage), so every reported
period is a mixture of affected and unaffected units whose proportions move. Read it to understand what a
winning build looks like; **do not draw it**. It is one shipped build's driver, the guard refuses a faithful
instance mechanically (BLOCK on both `test.same_puzzle_older` and `test.same_driver_older` against it, with
`driver.near` 0.19, the nearest driver on file by three times against a next of 0.06), and the honest
differentiation line cannot be written, because that card's driver already states the shape with its nouns
stripped and its `Lesson:` line states the generalisation verbatim, so any faithful instance fails its own
`Lesson:` test. **Reusing a proven device is legitimate; reusing a driver is not** (Part 6), and what made
that build ship was a device: a TRUE operational sentence that made the one decisive join look pointless.

**The linkage trichotomy, which is why the shape carries no stump without that device.** The mixture weights
have to be SHIPPED for the path to be computable at all, and the position variable ships with them, so a
reported row falls into exactly one of three cases and there is no fourth. It carries its cohort or regime
directly, and the construction is one group-by. It carries a unit key a register maps, and the construction
is one join plus one group-by, the same cost. Or it carries nothing identifying the unit, in which case
there is no within-period contrast and the profile is identifiable only from the published series, which is
the quantity the call is about: measured, a cubic trend with seasonal terms reproduces **90.5 per cent** of
the distortion path's variance (a cubic alone 74.9), so the distortion cannot be told from a real
deterioration. In the first two cases the designed route and the cheapest licensed route are ONE route,
measured at RMSE **0.0072** and a maximum of 0.0170 against the golden path on the clean truth, 2.8 and 3.3
per cent of its own level, by one join, one two-way group-by on (regime, position) and one reweight, which
is both the opponent's first move and the field's own standard output.

**The forward-facing variant escapes the group-by and lands in another family.** Set the as-of so the
affected cohorts have reached only the early positions while the graded path needs the later ones, and the
contrast has to be transported. The record does select one transport (excess Poisson deviance 723 to 1,417
for a constant multiple and 663 to 1,376 for linear in position against 7.6 to 30.4 for a constant additive,
on a bar of 4.0, with the designed route recovering the offset at 2.993 plus or minus 0.177 against a true
3.0), so determinacy holds, but the decisive step has moved onto choosing a functional form, and fitting two
forms and comparing deviance is readability test 5 and reaches the golden 20 of 20. That is the fitted
counterfactual family, not this one.

**Both directions the shape appeared to leave open are now priced, and both are dead.** Grading the path's
TURNING POINT instead of its levels gives **2.95 distinct turning points of 5** across the licensed family,
and it carries a trap that reads as a pass: **19 of 20 worlds have SOME family member naming the true
turning point** while the family spreads it across four quarters of an eight-quarter window (a true plus 7
against a family of plus 3, 4, 6 and 7). **Naming it is not the family agreeing on it**, and a screen that
reports the former has measured nothing. A structure whose POSITION IS NOT REGISTERED, so the position is
reconstructed from each unit's own history, gives **5.00 distinct paths of 5** at a spread of 4.72 against a
printed unit of 1, exact in only 3 of 20, with every licensed reconstruction (largest drop, local minima,
cusum reset, sawtooth least squares, pooled modal period) giving a different path in every one of 20 worlds. **And a second slot priced it independently and found it dies in a different place than the law
predicted, which is the useful half:** the POSITION ITSELF is recovered well, a grid-fitted harmonic putting
the median phase error at 1.04, 0.46, 0.27, 0.19 and 0.13 months as the amplitude-to-noise ratio runs 0.59
to 4.71, so the parametric horn does not bite the phase at all. What is free is **the CYCLE the phase is
measured against**, and every graded object built on a position needs it. So do not price the position's
recoverability and conclude the direction is open: price the cycle.

**The one-number test for whether a candidate is in the closed family, whatever its nouns.** Over one full
cycle compute `R = sum_q |G(q)| / |sum_q G(q)|` on the graded path, and count the path's sign changes. A
genuine per-case correction returns **R = 1.000 with 0 sign changes**, measured at sd(log factor) 0.35, 1.00
and 2.00 alike, because its operator acts inside a case and scales its value so every reported period moves
the same way. **R = 1 is an identity for the closed family, not a tendency**, so any candidate measuring R = 1
with no sign change IS a per-case correction in other nouns. Run it before any other screen; it costs one
pass over the clean truth.

**And it is what shows that ADDITIVITY DOES NOT ESCAPE THE CLOSED FAMILY'S BEHAVIOUR.** A propagation
correction is additive in cohort-position cells, so none of the six laws has a term to bind, and that is
true but not sufficient: three of four propagation members measured return **R = 1.000 with 0 sign changes**
anyway. The one member returning R above 1 is a RE-PHASING, whose counterfactual has to re-time events that
were never recorded, and that is exactly the member that then dies on determinacy: four licensed readings of
the re-timing cadence spread the graded figure a mean of 13.32 and a maximum of 40.52 against a printed unit
of one cent, about 1,330 times the unit, and the window-length dial does not open it (spread over signal runs
294.7, 1.790, 2.219, 1.730, 1.718, 1.789 at 2 to 12 periods, because a one-day cadence difference compounds
linearly in the window while the signal does not). **So R and determinacy are one dial read from two ends:**
a path that moves both ways is a path whose counterfactual re-times something unrecorded.

**The running-sum crossing is closed too, by an increment trichotomy**, which shuts the last non-multiplicative
ground this lane had left. A crossing's increments are either definitionally open, which is indeterminacy; or
recorded and exact, in which case the crossing date is a one-line cumulative sum over shipped columns, which is
rule application; or not yet recorded, in which case the quantity is a predicted value the history pins, which
is Forecasting and not this objective. The two apparent fourth cases collapse into the first: incomplete
increments put a completion estimator in the deciding position, and an unobserved crossing level puts its
estimator there, while a filed level is rule application.

**Removal and addition are asymmetric, and only removal forces the reasoning.** A change that ADDS units
leaves the counterfactual directly recorded with its own identifiers, so the construction is a filter on two
columns and there is no unit-of-analysis carve-out at all. Only removal makes the counterfactual absent from
the post-change record. Draw the removal side or draw nothing.

**And count concurrent occupancy, not just the shipped corpus.** Three live slots sat on one family at once:
the one that shipped it, one holding a cycle instance, one holding the exact-mixture-weights branch. **A
fourth slot there clones a concurrent sibling even where it clears every shipped card**, and `guard.py check`
cannot see it because those cards are not yet registered against each other. Run `guard.py slots` on the
mechanism's nouns AND the setting's, and read the wave's allocation table, before pricing anything.

**And the closed clause is wider than multiplicative: it covers an ADDITIVE per-case correction too, because
there the escape and the kill are one property.** Grading a level-dependent count is the named escape from
the monotone-summary kill and it does work, since no sorted column reaches the path. But the same level
dependence is why the per-case error does not average away: a count across a limit is discontinuous, so a
recovery always misplaces the cases nearest the limit. One property buys the escape and pays for the kill,
measured at 4.80 distinct paths of 5 for an unrecorded additive effect, a spread of 3.11 against a printed
unit of 1, and **0 of 16 joint cells**. So state the closed family as a per-case correction, additive or
multiplicative, rather than as a multiplicative one.

**The one-ended dial here reads off a single table, which is the cheapest-licensed-member law in its sharpest
form.** Sweeping a parallel run's coverage and precision, the standing family falls from 4.70 members to
2.00 while the cheapest licensed member's own hit rate on the golden path rises from 4 of 20 to 19 of 20,
and **0 of 16 cells** have both a unanimous standing family and the cheapest member missing. Determinacy and
reach are the same column read from two ends.

**The unknowns-against-cases axis is CLOSED too, and the reason is an identity rather than a measurement: the
shipped design matrix is simultaneously what closes the estimator family and what makes the construction one
line.** For a few shared parameters to be identified from many cases, each case's observation must be a known
function of the parameters of the handlers that case touched, and the organisation must SHIP which handlers it
touched or nothing is identified at all. So the pack is a design matrix plus an outcome, the link is forced by
the design (identity for a sum, log or cloglog for a product or a masked-cause series system), and the
decisive construction is one call on that matrix. Gate C and Gate F are therefore financed by the same object
and **the dial is one-ended by construction**. Three further measurements say the same thing from other sides.

- **Count the design's RANK, never its rows.** "Unknowns strictly fewer than cases" held in the count and
  failed in the only count that identifies anything: the routing's own design measured rank **34 of 36**
  unknowns at two years, **227 of 240** at forty units and **1,122 of 1,200** at two hundred, rank deficient at
  every realistic window.
- **A large case count can be pure REPLICATION, and then it buys a fork rather than precision.** 96,000
  fine-grained rows were identical to the 48 coarse rows in 20 of 20 worlds, because every fine unit saw every
  event of its coarse one. They added no information and they did add a weighting choice, which **moved the
  designated set in 10 of 20 worlds**. And the informative count per unknown is invariant to scale (1.00 at 6
  units, 0.79 at 40, 0.79 at 200), because events and unknowns both scale with the structure, so only the
  WINDOW buys information and it buys it linearly: the converged cell needed a record of order 500 years.
- **The cheapest-member law has an algebraic form, which is stronger than its measurement.** 0 of 16 joint
  cells had a unanimous standing family with the cheapest member missing, and there is no third cell to find,
  because **the cheapest licensed member IS a member of the family, so unanimity implies it agrees with the
  rest, and the only cell where the family agrees is the cell where it is right.** Measured alongside: the
  family fell from 4.30 to 1.05 distinct designated sets while the cheapest member's own hit rate rose from 0
  of 20 to 19 of 20, and at the realistic window the joint estimator's RMSE was 0.4489 against a golden
  boundary gap of 0.1449, a ratio of 3.10, so the set is seed hostage at any pack an operator could hold.

**The enumeration of shared-parameter constructions is closed with it**, each on a named kill: the additive
joint solve (a shipped build's driver); the log or cloglog solve (the same organ once the link is forced);
variance components (a variance-only screen); paired comparison or Luce severities; difference calibration;
stage-distribution deconvolution graded on a tail; capture-recapture over channels; conditional or eliminating
likelihood (a ratio of sums, which is the one-group-by route and a family member at once); flow
reconciliation; and feasible-set intersection of interval constraints. The shape is also already spent on the
portal in other nouns, as a common-point-of-purchase construction that a solver landed at proxy 94.5.

**Put the whole closure in one line: overidentification does not make the construction HARD, it makes it
FORCED, and the forced construction is the cheap route.** A third slot measured it on instrument-exchange
ground, 960 readings against 490 unknowns, overidentified by 470, with the focal parameter recovered to about
1 per cent: the overidentified joint solve **collapses to the pairwise group-by** at a maximum absolute
difference of **5.129e-13**, correlation 1.00000000 and an identical graded count in 10 of 10 seeds. And the
cheap route is not merely equal but better: one regression per pair landed the verdict 23 of 24 at a
**smaller** recovery error than the designed solve (0.989 against 1.154 per cent), so the ladder is level at
best and inverted on precision. The lever is real (no correction at all lands 11 of 24) and it buys nothing.
On a graded LEVEL instead of a verdict the family spreads the share 12.2 to 45.8 printed units and agrees in
**0 of 12** worlds at the largest case count.

**A precise shared parameter does NOT rescue the level-dependent count**, which closes the last cell anyone
might have hoped for: with the parameter known to 1 per cent the exact count above the limit is reached by
only **2 to 6 of 20** on the best route, because the misplacement sits in each case's own reading noise and
no amount of precision in a shared parameter touches it.

**The identification channels are exhaustive, which is why the enumeration can be trusted.** A few shared
parameters can be identified from many cases in exactly three ways: a within-case contrast, a regression on a
shipped column, or a moment of the readings' own distribution (which is a dispersion, closed by the
variance-only screen). And what a device or handler parameter can BE is exhaustive too: location, scale,
memory, dispersion, threshold, error rate on real samples, drift rate, all seven closed or spent.

**The identity is measured to machine precision, and the axis's premise holding is exactly what kills it.** A
second slot built the design deliberately well: 3,840 cases against 491 unknowns at 7.82 cases per unknown,
with the analytic standard error per shared parameter at **0.5152 points over 59 worlds against a filed
tolerance of 5.0**, a tenth of the decision's margin and a fourteenfold improvement on an earlier slot's 6.96
points against a 3.0 lever, because a joint solve borrows every path through the connected roster instead of

**One prediction this screen corrected, which is why the pincer is checked and not assumed.** The rank

**The test:** correlate the construction's output with the plainest column of its own forcing file across

### 2.1 The readability screen

## Part 3. The ladder

Three to five rungs, four by default, each a defensible analysis climbed by refusing it: rung 0 the
default path, 1 the obvious correction, 2 the sophisticated one, 3 the silent decisive move (two fall to
one correction, six read as ambiguity). **Rung 0 is never shipped:** no artifact ranks the candidates
wrongly, at any depth, except a declared wrong-basis distractor (`dataset-generation` §8.3); a dimension
table the naive pipeline needs is rung 0 (42). **Every rung** reproduces from the raw files, names its own
candidate, dies to exactly one shipped fact or construction, and is satisfying to stop at; a loop-fixable
slip (58 v5) or one group-by (36) is no rung. Cleaning sits at rung 1 or 2. Depth is a Gate F device,
never a Gate G defence. **Read rung 0 off what the shipped files name, free text included:** remarks naming
the counterparty each affected case waited on hand that candidate to the natural pipeline whatever code sits
beside it, and the one entity present only in the later period is the first thing a two-period comparison
lists (500 v1). **Measure the decisive rung on the graded name and the graded figure separately:** a rung that
only changes who is blamed, while the counterfactual figure is the same whoever is blamed, is worth nothing on
the figure, and a response skipping it files the golden figure (500 v1).

**Price the estimator's own standard error in the same breath, in the graded figure's units.** The ceiling
test is necessary and not sufficient: a decisive step whose estimator's standard error exceeds the ladder's
margin cannot rank, however large the bias it chases. task198's architecture 2 priced 9.4 points of
available bias against 4.5 needed, with the two separations financed by independent parameters, and died
anyway, because the step had to recover a per-interviewer differential and the record measures it only
through that interviewer's own out-of-unit workload: 33 observations at a median field load, a standard
error of 6.96 points against a golden rise of 3.0, so the correction injects several times more noise than
the bias it removes and lands on whichever small unit drew unluckily (the golden named in 2 of 12 seeds).
A one-point standard error there needed 1,600 observations per interviewer per quarter against a realistic
50 to 80, and noise falls as the square root, so no feasible pack closes it. **Prefer a decisive quantity
the whole population estimates** (a variance component, a rate over every unit) **over one estimated
per unit from that unit's own thin slice.** And watch for the dial that fails at both ends: there, a
persistent differential made the additive control a solver reaches for the right analysis, so the schema
tell reached the golden, while a non-persistent one left the within-period estimator too noisy to rank, and
no setting satisfied both.

**A decisive step that moves a variance cannot carry a ranking**, because the variance that reorders the
candidates is the variance that randomises the quantity they are ranked on: the lever and the noise are one
number, so the dial fails at both ends and the two ends are the same end. Compute the lever's size in the
ranked quantity's denominator and that same quantity's contribution to the numerator's spread, and if they
are one variance the step cannot rank. task198's architecture 2 ranked units on a change over its spread,
where the spread is `sigma_b sqrt(HHI_cur + HHI_cmp)`: the two-interviewer unit at a workload concentration
of 0.642 carries 1.13 `sigma_b` against the fourteen-interviewer unit's 0.38, a ratio of three whatever
`sigma_b` is, which is exactly what flips the ranking, and that same spread is the random swing in the
measured change (intended rises of 0.4 to 5.5 points against realised changes of +17.1 to -17.2, the golden
named in 2 of 14 seeds). Large enough to flip is large enough to randomise, and shrinking `sigma_b`
stabilises the numerator and removes the lever in one stroke, so no feasible pack closes it. This is not a
Gate C finding: on any one cut pack the analysis gives one answer and the estimator family is closed. It is
a failure to be buildable to specification, because the rungs, the margins and the loud and golden roles
would all be hostage to the seed. **Judge-against-noise mechanisms stay sound where the answer is a verdict
on one named candidate, or a flag against a stated threshold on a given pack; they cannot decide which of N
is largest.** Reaching the verdict shape is also the repair: task198's architecture 3 keeps the same world,
pack and variance component and moves the decision from a pick of one region to a characterisation of one
named region's move, which puts the whole lever on a threshold the pack is cut against.

**What actually decides it is the distance to the decision boundary in units of the lever's own noise, so
measure that number rather than preferring a shape.** A ranking of N has N minus 1 boundaries and the
nearest is usually close, which is why rankings nearly always fail; a verdict has one boundary and can be
placed far from it, which is why verdicts usually survive. Usually is not a licence. task198's
architecture 3 put the flip 61 per cent of the variance component away, about fifteen relative standard
errors and four hundred times the estimator family's own spread, and holds. task200's first direction was
a banded verdict on one named facility and died anyway: the lever was a measurement variance removed from
an observed variance, the graded figure's noise was the sampling error of those same two variances, and
over 40 seeds the golden ran 1.108 to 2.161 mg/L against a truth of 1.471 and a band edge at 2.000, so the
golden's own tier took both values. Under one standard error to the boundary is seed-hostage whatever the
decision's shape. Two further numbers from that screen are worth carrying: eleven estimator forms a
competent analyst would use spread 0.52 mg/L on average against 0.04 permitted at the printed precision,
over by about thirteen times, and the forms all agreed on the tier within any one seed, so only the
across-seed run exposed it. And where a variance lever is taken at all, take it on a percentile rather
than on a tail share: the percentile's lever is linear in sigma while a tail probability's noise blows up,
which on that ground was 7 standard errors against under 1 for the same idea.

**A variance-correcting step cannot be silent on a call about a change while the unit's own history is in
the pack**, because the component that makes the supplied interval wrong is the component that makes the
history wobble. The two are the same number from both sides: a differential redrawn each period inflates
the variance of a change and is readable off the series, while a persistent one is invisible in the series
and cancels out of the difference entirely, so there is no setting at which the correction matters and the
series does not show it. task198's architecture 3 died on it after ten listed reflexes all landed wrong at
z 2.95 to 4.60: the eleventh, judging the rise against the region's own quarter-to-quarter variation, gave
five consecutive changes with a standard deviation of 9.15 points against a 7.64 rise, so z 0.83 and the
golden verdict in 5 of 5 working seeds, with no component, no workload log and no re-formed replication
anywhere in the route. Consolidating the panel left the history's own change spread at 9.06 and broke rung
2 instead. Sound only where the unit has no usable history in the pack, or where the call is about a level
rather than a change. One computation prices it: take the unit's own period-to-period standard deviation
and the correct standard error, and if the first is within about a factor of two of the second, the
decisive rung is readable off the series.

**Where a design withholds the exposure a quantity scales with, check every adjustment the pack already
publishes for another reason.** A standardisation performed on an observable that correlates with the
withheld exposure is a free partial recovery of it, and it costs the solver no construction at all.
task194's architecture 6 withheld patient movement as the driver and died there: the excess a solver builds
by hand designated nobody at every confound strength, while the pack's own published standardised ratio,
read straight against the filed tolerance, reproduced the golden set, because the units that take more
handovers are the units that take sicker patients and case-mix standardisation absorbs enough of the
withheld driver to put the right two units over the line. **And the enumeration has a second axis: the
parameter range the world makes plausible, not only the value the generator uses.** That kill fired at a
confound correlation of 0.6 and not at 0 or 0.9, so sweeping one setting would have missed it; sweeping the

correlation it still names both true members plus one false positive. Tuning the confound away from the
middle is not a repair, because the build would then rest on asserting that case mix and patient movement
are uncorrelated in a hospital, or correlated so strongly that standardisation overshoots, and a reviewer
grants neither. On healthcare-delivery ground this is close to structural rather than incidental, since
risk adjustment is what that domain publishes most and nearly every patient-flow driver correlates with a
clinically standardised observable; that last claim has a mechanism but too few builds on file to test it

**The reflex sweep is only as good as the enumeration behind it,** which is why it is run as code and why

**When the decisive quantity is recovered exactly from a subset of the records, ask what else that subset

recovered quantity is constant: one revealing row is enough. And the exactness cuts both ways, which is
the trade to price: what made that step's estimator standard error 0.0000 per cent is what made the easy
recovery exact, so the two cannot be separated by tuning, and driving the revelation to zero hides the
quantity from the decisive route as well. Here censoring is revelation. **The same screen closes a whole identification family: "estimate the nuisance where the signal

**Where three screens close a cell, invert the draw.** Three cells closed in one sitting, each reporting
that `guard.py check` fired no axis ban and the nearest driver sat at 0.08: the window was open and the
mechanism was missing every time, because each draw started from the field's own estimator and the field's
characteristic quantity is what gets spent first. Start instead from **the file that does the forcing**:
the shape of the corpus's strongest hold is an unobserved quantity whose forcing input sits in another file
at another grain, with the construction forced by arithmetic rather than by a fit. Enumerate the files the
organisation actually keeps, ask of each what it pins that no other file pins, and take the quantity that
file forces. A draw that begins with the estimator and looks for data to suit it has the search backwards.

**Enumerating the files is step one of two, and on its own it is necessary and not sufficient.** Step two
is the proxy screen in 1.6a's fourth clause, run on the construction before any separation measurement,
because a file that pins a quantity usually also publishes a column summarising it. Measured 5 for 5 on
one ground and 8 for 8 across its siblings. The worked warning: a barrier-grain investigation record is
genuinely the only file that observes several barriers jointly on one occasion, which is what the
enumeration is looking for, and the construction it most obviously forces is proxied at **+0.9960** by a

forces, and expect the obvious one to be the proxied one.**

**Step three, which five closed cells wrote in the same words without conferring.** The file that does
the forcing is not enough either, because the construction it forces still has to escape every screen
above, and the screens between them leave exactly one shape standing. Three independent passes on three
unrelated cells (a transit constabulary's patrol record, a public health unit's outbreak line list, a
provider network's statutory returns) each ended by naming where a later pass should start, and the three
notes describe one thing: **the correcting quantity is one per case, forced by a second file
at a finer grain than anything the main file carries, no part of the record escapes it, and the construction
that recovers it has no free parameter, so its standard variants agree on the graded figure.** Each clause
is a screen answered. One per case, not one per unit, clears the one-number screen and the benchmark screen
at once, because a per-case correction cannot collapse into a single comparison. Nothing escaping it clears
the partial-coverage screen and with it the attaining-subset screen, since there is no unaffected part to
filter to. No free parameter clears the determinacy screen, because an estimator family is what
returns more than one answer. **That is 1.6a's test, do the standard variants agree on the graded figure, and
it is not the stricter clause that the second file's quantity enter linearly and by identity.** The stricter
clause is self-defeating and was measured so: hold it and the per-case quantity is a shipped quantity, so the
graded quantity is a deterministic function of shipped columns and the construction IS the cheapest
one-group-by route, measured at corr +1.000000 with a maximum absolute difference of exactly zero on a
duration correction and 7.1e-15 on a count correction, with standing family spreads of 3.52e-06 against a
printed unit of 0.01. That is rule application, which rule 3 bans as the decisive step. A fit is therefore
licensed where the design fixes the functional form and leaves no free exponent, lag, decay or distribution
family: the one build on file with Gate F strong recovers its per-case quantity by least squares on a linear
ramp between two shipped endpoints, which is a fit that returns one answer, and it satisfies 1.6a's test
while failing the identity clause. **Making the correcting quantity unobserved restores the analysis and
reopens the estimator family in the same stroke**, so the clause to hold is no free parameter, never no fit:
a free damage exponent spread one graded figure 165.9 per cent of its own level across 2.70 designated
classes of 5, and a free matching tolerance spread another 22.2 printed units across 1.45 of 6. Finer than any attribute the main file carries is what stops a
cross-sectional control, a stratification or a reweighting from reaching it. A candidate failing any one
clause has a named route to the golden before a world is drawn, and the five closures are five instances of
exactly that. **State the one-group-by route to the call, in one line, before the first harness**: the five
passes that measured it found it on the second measurement, never the tenth.

**The last clause was added by a measured death, and it is the one a draw will argue with.** "Forced

to 4 on one draw, with the graded rate spreading **107.9 per cent of its own level**, 255 times its printed

**Run step two as algebra before you run it as a correlation, and it answers with certainty.** Write the
construction as a function of the forcing file's own column and ask whether it is affine in it. If it is,
that column plus one regression **is** the decisive step, and no amount of Layer 1 between the files
changes it, because mess delays a join and does not break an identity. Measured on a blend-unmixing draw
whose graded quantity was a mixture by construction, so affine in the published mixing share: one

input being per unit clears screen 1, and being affine in it kills the draw anyway. One computation, before
any world is drawn.

**A documented transformation of the recorded values cannot carry a silent rung.** Where the decisive step
inverts a transformation the record has already applied (a per-window maximum, a per-group median, a
decimating filter, a rounded or banded publication), the draw is caught in a pincer with no third side:
either the pack documents the transformation, and that sentence is readability test 1 sending the solver
straight to the inversion, or the pack does not, and the step is unidentifiable because nothing in a
record of maxima measures that it is a record of maxima. So **the forcing file must pin a structure, an
order, an opportunity count, a condition, never a transformation of the values**.

**The mandated-indicator law, which tells you where the proxy screen fires before you look.** Step two's
one-column precis is usually an accident of a file, and on some ground it is required output. Where the
deciding organisation is obliged to publish a quality indicator for the very process whose record you are

statistics office's quality framework makes it publish the response rate, the link rate, the edit rate and
the imputation rate, so a quantity forced from any of those production logs has its correction published
beside it, measured at corr **+1.0000** with the one-divide route and the truth reached **20 of 20**, where
the designed construction's own lever was 3.028 per cent. The escapes the inversion names (a timing
condition, a completeness condition, an incentive) do not help here, because on that ground the
completeness condition **is** the published rate. So on regulated ground, force the quantity from a file
that is not a process log of the deciding organisation, or accept a shipped proxy and draw something else.

**A screen coming back clear is information, and the proxy screen has a structural form to ask first.** The
forcing file's own column is the wall on most ground, and it is not automatic: one candidate measured corr

not only whether the forcing file happens to publish your correction, but whether publishing it is what the

**Operations ground is adverse to a silent rung, as the mandated-indicator law's mirror rather than an

what the field estimates and readability test 1 pushes it away from anything a filed sentence names, and
there the two pull in opposite directions. Three candidates running, the quantities with no entry in
anybody's dictionary were the ones that were not operations quantities at all.

**One role rule the same sitting earned twice, and a second the same wave earned three times.** An

register while a pass runs, so a written ban table is stale within the hour and is wrong in both

**The pricing sequence, run in this order before a word of design:** name the residue the filed WHAT leaves
(a knob fails at once, only a method survives); price the move available against the move needed; price the
standard error of whatever the step must estimate; check whether the lever and the ranked quantity's noise
are the same variance; where the step corrects a variance on a call about a change, check whether the
unit's own history already estimates what the step computes; and where the quantity is recoverable exactly
from a subset of rows, check what that subset hands over. Each is one computation on the clean truth and
each has killed a family that paragraphs of argument had left open.

**Price the move against the ceiling before screening a candidate at all.** Compute two numbers: the points
the call has to move for the candidate to decide anything, and the largest move the affected population
could produce if every one of its records flipped. task198's cutover family needed 8.79 points and could
produce at most 2.644 on any queue, so one computation killed a whole family that three paragraphs of
argument had left open. Run it first, on the clean truth, before any screen that costs design time.

**Two separations financed by one quantity are priced together, before the design is accepted.** A ladder
usually needs two inequalities to hold at once: the easy route must lose on the record as it stands, and the
answer must win once the decisive step is taken. When one quantity pays for both (the uplift a correction
carries, the drift a restatement carries, the lag a vintage carries), they trade off directly, and buying
one spends the other. Compute the budget in the graded figure's own units, compute what each separation
costs, and check the sum before any data is cut: task194's architecture 3 had a 27.25-complication budget,
spent 18.38 of it on a 2.35 flip and a 16.03 margin, and clearing both comfortably would have taken 33.14,
so the point that cleared the margin left the flip at a third of a standard error. Scale is rarely the
answer, because the budget grows with the count while its noise grows with the square root, so closing a
shortfall of that size means an entity several times the size of the one the decision is about.

**Price the decisive step's own standard error before measuring any separation.** Where the step recovers a
latent quantity from records that observe each event only as an interval it fell in, the estimator has
sampling error of its own, and a ladder whose gap at the decision is smaller than that error is seed-hostage
rather than designed. It costs one solve of the censoring likelihood's information matrix, no draw and no
sweep, and it is run before the magnitudes are tuned. One build measured a first world at a gap over standard
error of 1.04 and a second at 1.71 on the same mechanism, the difference being where the interval length's
variation sat.

**State the dial's test as the pass condition, because its failing form is easy to write backwards.** The
build needs **some** setting at which the separation at the decision is real (the nearest wrong rung clears
the boundary by the floor, in another printed cell) **and** the licensed family is unanimous on one printed
call. The dial is one-ended when no setting has both, which reads as: every setting with a real separation
has a **split** family, and every setting with a unanimous family has **no** separation. A unanimous family
is what Gate C wants, so "real separation and unanimous family" names the cell the build is looking for, not
the cell that kills it. One brief got that sentence inverted and described a passing build as the refusal
condition; the agent reading it noticed and applied 1.1 instead, which is luck rather than process.

**Count the dial jointly, never as two marginal patterns.** "Every setting with a real separation has a
unanimous family, and every setting with a split family has no separation" is checkable only marginally, and
marginally a dead build can look mixed: one measured 245 of 300 settings with a real reach and 66 leaving the
record quiet, which reads as plenty of room. Counted jointly it was unambiguous: **22 settings had both, 0 of
those 22 had a unanimous family, and 0 of 320 draws cleared reach, unanimity, the rung floor and a mid-bin
call together**. Count the cells that pass every requirement at once, and list the requirements before
sweeping. The marginal form let one measurement pass that the joint form killed.

**Assert a clearance for every rung, not an empty set.** A rung's assertion that its answer set is empty,
or that it names another candidate, says nothing about whether it is satisfying to stop at. One build shipped
with three reflex rungs sitting **inside 1.15x of its own decision boundary** (clearances 1.061, 1.092 and
1.106) while every generator assertion was green, because the checks asserted each rung's set and only the
golden's margin. A rung nine per cent under the line is not a stopping point, it is an alarm that sends the
solver on, and that is the magnitude failure mode itself rather than a near miss of it. So every rung's
highest figure clears the decision boundary by the same floor the golden must clear it by, asserted in
`checks.py` alongside the set.

**Enumerate each reflex in both its rate form and its count form.** The two are different constructions and
the count form is usually the cheaper, so it is the one a solver reaches. One build swept losses per
climbing or descending flight **hour**, at 32.0 and 36.6 against a boundary of 40.0, and never losses per
climbing or descending **traversal**, which files 42.3 and lands the call: one comparison per row instead of
a duration sum. The sweep lists both forms of every reflex before any of them is priced.

**The dial spends the rung floor too, so price it with the rest.** The separation at the decision and the
licensed family's unanimity are the two the screen usually names, and on many grounds the binding constraint
is the third: the 1.15x margin on the nearest wrong rung. One build's shipped setting was already the widest
its floor allowed, with the floor crossed one step further out and the nearest rung sharing the call's own
printed cell two steps beyond that, so every direction that bought reach spent the floor one for one.

**One dial or two, and the test that tells them apart.** On interval-censored ground the flat reading's error
and the estimator's variance are both driven by interval length over the width of the feature being
recovered, so tuning that ratio moves along a curve and buys nothing: widen the feature to make the estimator
precise and the flat reading stops being wrong. They separate only when **the flat reading's error comes from
the variation of interval length across the decision's own candidates** rather than from length itself.
Measured both ways on one world: a feature 1.05 hours wide against windows of median 16 gave a gap over
standard error of 1.04 and a slate that moved with the seed; moving the length variation onto the candidates
(weekend closures of 39 to 64 hours against midweek ones of 14 to 16) gave a gap of 76.8 against a standard
error of 38.3, the same slate in 20 of 20 redraws, and the flat reading still 1.35x off. So draw the variation
across the candidates, never the feature against the interval.

**A marginal standard error overstates an ordering's uncertainty, so count redraws instead.** The error on one
graded cell and the error on its neighbour are correlated through the record's own fixed total, so a ratio of
the decision's gap to a single cell's standard error is conservative and can read as thin when the ordering is
in fact stable. The honest check is the redraw count: the build above read 1.71 on the ratio and 20 of 20 on
the redraws, and the redraws are what the ladder stands on.

**The arithmetic, on paper before any row.** Position, margin, separation and dominance as
`dataset-generation` §6 asserts them (4th or 5th on rung 0, no margin under 1.15x). Then: one live degree
of freedom in the graded quantity holds no ladder (49); the decisive move is never the smallest (37);
every correction walks one way and only the decisive move reverses; a quantile absorbs a selection rung
(44) and a share cancels one moving both terms, while totals, counts and levels carry rungs, so each
rung's worth is computed on the graded quantity, never an intermediate; every grid cell is a named wrong
answer or outside the floor, n monotone corrections at f needing a reversing g >= 1/((1 - floor) f^n),
partial applications swept, hazards adding path length but no cell, the answer extreme or bracketed (L3 to
L5, C4); every single-error cell files a feasible figure (44); and a saturated grid takes no rung, while
cutting one can buy separation (45).

Stack two to four mechanisms from different gaps, the decisive gap not rung 1's; same-pattern stacking is
one mechanism twice. **A hold** (`signal_vs_noise_or_hold`) is determinate when a computed blocking
quantity reproduces, every candidate fails for a named reason, the prompt licenses a non-pick on equal
footing without advertising it, the default path still names a candidate, and the note says what would
have made a pick. "The data is unclear" is a hedge.

## Part 6. The draw: a unique stump

A stump recognisable by its shape has lost; a template is sent back however far apart the surfaces are.
**The card:** `guard.py recent` and `coverage`; draw every card axis independently (the objective from the
graded quantity's tense, people from `guard.py names`); check `corr(decisive measure, unit size)` at the
decision grain (57 died, +0.98); `guard.py check`, BLOCKs cleared and WARNs answered; `register` before
the ladder.

**Where a fresh stump comes from.**
- **Ask which file does the forcing before asking which statistic is smarter.** For a quantity estimated
  per unit from that unit's own records, a construction is forced in exactly three ways, and each is dead
  for its own reason: **exact arithmetic** makes the quantity observed, so the step is rule application; a
  **non-parametric** construction is a stratification, which is the opponent's first group-by and reached
  the truth 20 of 20 where it was measured; a **parametric** one reopens the estimator family, 2.85
  distinct designated sets of 4 at a serial dependence of 0.45. There is no fourth case, which is why
  across eleven measured mechanisms the dial that closed the estimator family was always the dial that
  made the quantity observed or the naive route right. **The escape every ship took is not a cleverer
  statistic: the forcing input comes from a different file at a different grain, whose variety no
  stratification of the decision file reproduces.** An archive giving a scheduled trajectory only as its
  endpoints, a second capture channel largely produced by the unit's own follow-up, a record of the
  observation effort behind the counts. So the draw starts from the file that forces the construction, and
  a candidate whose forcing file cannot be named is not a candidate.
- **The field's estimator meets the data's process.** List the field's methods for the deciding quantity
  and the generic move a generalist makes instead; then write how each file's rows come to exist (who
  records them, when, by which route, what they cannot see). Pitfalls live where recording differs from
  the event: delay by route, reporters not yet filed, checks that see a unit just before resetting it,
  replacements restarting a wear curve, detection falling as targets grow rare, sub-units sharing a
  budget, a lagged response to a shared driver, a yield moving with the base rate while error rates hold,
  competing exits left in a base, a hazard by time since entry.
- **A latent structure no column names:** the conditioning variable that makes the pooled quantity wrong
  (route, reporter, household, entry date, pool mix), rebuilt from a history, a join or a grouping.
- **Every reflex lands wrong:** list the reflexes for this pitfall (pool, aggregate scale, stratify on
  visible attributes, trend, reweight, shrink, add a control); each files the default or another named
  wrong answer (181, 445, 446, 230). A reflex reaching the golden spends the stump.
  **Run the sweep as code before the ladder's numbers are measured, not after.** The sweep is cheap, about
  a minute on a cut pack, and it decides whether the mechanism can carry a ladder at all, so measuring
  separations first spends the design time twice: task194's architecture 3 had every filed floor cleared,
  1.50x on rung 0 and 2.008x on the decisive rung, and died anyway because 6 of 22 reflexes reached the
  golden, the worst at 3.47x.
  **Orthogonality is a construction, not a check.** With the 9 to 16 units a slate-valued call carries, a
  driver drawn independently of the visible attributes still correlates with one of them up to about 0.75
  by chance: task182's first model hit +0.751 against night share on its first draw. Residualise the
  driver against every visible attribute at draw time, which holds the maximum absolute correlation at
  0.000, and then assert it. Drawing independently and testing afterwards costs a redraw every few seeds.
  **And a slate needs as many real effects as it has places.** An internally standardised score puts every
  non-anomalous unit at exactly 1.00, so a slate of k has its boundary inside the noise unless k units
  carry a real effect; task182's first sweep failed on that before its realism problem even appeared.
  **What makes a reflex reach it is a correlation the designer put there.** If the thing that creates the
  signal also predicts the outcome's level, a finer standardisation gets the answer for free: there the
  lag's depth followed the complication groups, those groups come from old, comorbid, long-staying
  patients, and those are exactly the patients the published standard under-adjusts for, so holding the
  pool to every visible attribute arrived at the golden with no maturity analysis at all. So the signal's
  driver is chosen orthogonal to everything that predicts the outcome, the association between the two
  measured and asserted near zero, and no single visible grouping (a site, a specialty, a vintage flag)
  may isolate the rows it acts on. Where the signal lives only in the time structure, no cross-sectional
  control can remove it, which is the property to engineer for.
- **Wrong now:** the default construction is wrong on the data in hand; a record blessing the naive method
  until the window breaks it (27 of 30 builds) is blocked.
- **Under-used ground first, and read the unspent list for why it is unspent.** Pick the strategy, then
  the data. Count the strategies never drawn on the objective in hand, then strike the four the guard flags
  for semantics risk (`time_semantics`, `grain_or_unit`, `identity_resolution`,
  `stated_rule_hard_construction`, with `withheld_rule_corpus_fit`), because rule 3 bars them from deciding
  a call and a list made of them is unspent precisely because it is undrawable. **What survives that strike
  is the draw, and it is easy to miss:** six consecutive passes on one objective each redrew
  `stump_strategy` off a live ban and each landed on a spent family, while `binding_constraint` sat unspent
  on that objective across 34 cards with 12 uses elsewhere and no semantics-risk flag. Its condition is in
  1.4 gap 3: legal only where the metric is correct and an unchecked constraint removes the pick while
  re-placing nobody, never "their metric misleads".

**Test it against the cards and the record.**
- **Read the mechanisms on file first:** `guard.py mechanisms --objective <o>` (and `--gate-g <g>`) prints
  every driver and earlier architecture on that ground in one screen; write one line on the insight each
  spends and draw from what they leave. The driver score misses a mechanism told in other nouns: two task500
  re-roots passed `check` at 0.05 and 0.08 and still repeated 109's and 111 v1's drivers.
- **Abstraction test:** strip the nouns from your driver and the three `guard.py nearest` returns; one

- **Same-puzzle test**, answered in the note: gap, decisive pattern (or G-code) and decision type equal to

- **Standing bans** (`fingerprint`): every card axis from the pairing to the people against the last three

- **The record:** nothing drawn is dead (`strategies.md` Part 6, `shipped-ledger.md`), the pattern's

- **The library test:** if the golden is a card's method applied as the card states it, a blind reader
  lands it (1.3). Name the judgment beyond the card that the data settle and the default path misses, or

**No monoculture.** The guard blocks a strategy within three builds and warns at three in twelve: rotate
the strategy, Layer 2 family and gap across the batch. The semantics-risk strategies (`time_semantics`,

**The pin:** one filed sentence at authority naming the observable (Part 4). **The confirming corpus,**
only for a forecast chosen by honest back-test or a filed criterion shown to select one method, under C2
(`forcing-the-answer` Part 2); it never recovers a rule, refutes the naive read or blesses the wrong
method, and every outcome in it reproduces. A twin pair kills a lookup (O1). **Distractors:** two or more
files the solution never reads that look worth weighing, named only in `metadata.json`, never the stump.
**Voices:** optional, at most two people with beliefs, never a roll call or a quoted ranking; a rival
method arrives as the shortcut, never a document filed to be refuted. **Context artifacts** never rank the
candidates. No organ ships because earlier builds shipped one.

## Part 8. Diagnosis and repair

A diagnosis comes from the judge or the portal, never a solve in the main thread; returned tasks take
`/fix-determinism`, `/fix-rubric`, or stage 2 when the call landed (`build-pipeline`, Returned tasks). Diff each response against the golden cell by cell: the step it never took
is the finding, and an assumption every response holds unchecked is where to change the world.

- Landed on the default construction: make it wrong, a rung below rung 0 from another gap.
- Executed the decisive step as a work order: move it off every sentence and column, or re-root if only a
  plant stays silent. Named the quantity and argued it away: file the criterion, never the method.
- Reached every insight and defended another answer from a file, or read a term two ways: a fork; add the
  `SF` row and converge (`determinism-check` §2). An undesigned wrong candidate: close that reading.
- The last rung never moves the ranking: widen the edge or shrink the carried advantage. A control quoted
  back: tie it under every basis, or cut it. Missed the call yet scored high: rebuild the asks. The name
  right, figures wrong, repeatedly: re-root so the name is not graded. "The figure looks wrong": Gate G;
  rebuild, never harden.

**Harden, in order:** a rung from another gap below the decisive one; the discriminator behind a join; the
pin's evidence split across two documents; the winner's default-path rank worse; a conditioned yield; the
corpus tightened. **Never** noise, removed evidence, an invented threshold, harder parsing, a wrong-answer
artifact, or a deleted signpost that carried a parameter. **Stop rules,** written before the first portal
test: two exact solves by different routes re-root the ask; two determinism repairs that each made their
rung a reading re-root the difficulty; repeated solves change the decision, not the mechanism. One
mechanism per repair, a rule with the records that reproduce it, the dead end written when it dies.

## Part 9. What is dead

`strategies.md` Part 6 lists every death and its replacement; read it before every draw. The commonest: a
golden default, a reading, a quantity a sentence or the schema names, a reflex, a control that nominates
or refutes, a filed rule over filed candidates, a dated cutover, a validated decoy.
