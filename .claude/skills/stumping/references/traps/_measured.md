# The measured trap catalogue

> Measured on the client's own accepted tasks: four runs of the current model on each of 64 accepted tasks where it averaged under 0.70. A task counts toward a trap only where that failure was a decisive miss that cost the recommendation or its key numbers, so one task can feed more than one trap. **This is the ranking to draw the decisive rung from.** The catalogues beside it in this folder describe trap families by objective; this file says which of them the current model actually falls into, how often, and what the build looked like when it did. A trap that only works because the prompt is vague gets sent back, so every recipe below is built into the evidence.

**How to read the counts.** `count` is the number of the 64 tasks the trap decided; `under 0.50` is how many of those scored under the pass bar. The top four traps between them decided 37 of 64 tasks and share one architecture: a published control set, a governing clause that makes exact reproduction the condition of using a method, a unit or population the file layout does not show, and an obvious construction that matches most but not all of the controls. Build that architecture first and add a second, quieter trap behind it.

## 1. Reports a failed back-test, ships anyway

**Decided 11 of 64 tasks, 9 of them under 0.50.**

**What the model does.** The current model rebuilds the method, runs it against the published figures, and writes down that it matches only some of them. It then treats the mismatch as a caveat and ranks, certifies or adopts on that method anyway. Runs on the same task often land on different winners because each kept a different method that does not reproduce.

**What pulls it there.** The prompt asks to show the published figures beside the rebuilt ones, which reads like a disclosure item rather than a pass or fail test. A method that gets the ordering roughly right makes the remaining misses look like rounding or stale history.

**What the data required.** A governing clause made reproduction the gate, so any method that misses a published figure cannot be used. The analysis had to keep changing the unit, population or treatment until every control returned exactly, then apply that method unchanged.

**How to build it.** Publish a set of prior-period figures (means, certified cells, a signed ranking) produced by a method the documents do not spell out. Write a clause that makes exact reproduction of every published figure a condition of using the method. Design the obvious construction to match most but not all of them. Make sure exactly one construction reproduces all of them and that it changes the decision.

**How it goes wrong for authors.** If two constructions both reproduce every control, or the controls are rounded so coarsely that several fit, the answer is not pinned. Controls that the correct method itself only matches within rounding make the gate unfair.

**Where it happened.**

- *Adopt the arrival-based 2026 cover schedule with GMR at 50,670 minutes at p90* (model mean 0.13). Its own run-back reproduced only 19 of 24 published means, yet it set the GMR p90 boundary at 55,615 minutes against 50,670.
- *Certify the FY2027 rail crossing cycle at 23.8 collisions prevented for standard apportionment* (model mean 0.17). Accepted a factor table keyed on improvement type alone that reproduced 10 of 14 certified district cells, and certified 28.5 collisions prevented at full apportionment against 23.8 at standard.
- *Act on the Brennan Hale move to Wyburn Gate with a site travel plan and bus link* (model mean 0.21). Stated that its tabulation returned only 24 of 32 published sector means, then backed the wrong scheme with an area-wide rise of 2.5 minutes against about 1.5.
- *Allocate the additional pick shift to NM01 Farsley RDC on 52,959 projected excess cases* (model mean 0.56). Printed that its projection reproduced none of the 10 prior-review cells, kept the right depot, and put the gap at 5,080 cases against 7,747.

## 2. Counts file rows instead of the real unit

**Decided 11 of 64 tasks, 7 of them under 0.50.**

**What the model does.** The current model takes the unit of analysis from the row grain of the main file: one order line, one housing record, one letting row, one award, one fleet number. Every downstream figure inherits that unit, and some runs say outright that the documents do not allow splitting or grouping rows.

**What pulls it there.** The file ships one tidy row per record with a ready field to threshold or sum, while the governing document defines the unit in words the layout does not show.

**What the data required.** Build the unit the domain defines by grouping, splitting or linking rows (a receipt, an applicant unit, a stall, a budget period, a continuing hire), and confirm it by reproducing a published figure.

**How to build it.** Choose a unit that the governing document defines but no file stores directly. Ship records at a finer or coarser grain so the unit has to be built by grouping, splitting or linking. Publish at least one prior figure computed on the true unit so the grain can be tested. Make the row-grain answer differ enough to change the decision or the headline.

**How it goes wrong for authors.** If the unit rule is written nowhere and no published figure pins it, two grains are defensible. Avoid grouping rules that rest on fuzzy text matching the data cannot settle exactly.

**Where it happened.**

- *Estimate 2,591,394 applicant units eligible for the Winter Relief Grant at 185 percent of the poverty guideline* (model mean 0.17). Counted one applicant unit per occupied housing record and committed to 1,200,900 against 2,591,394, while reporting that the November allocation could not be replicated.
- *Report 11,667 stalls traded at member markets in the year to 31 March 2026* (model mean 0.21). Counted one stall per permanent or seasonal letting row (16,197) against 11,667 stalls under the adjacency convention last year's table pins.
- *Certify the Cottonwood Match Fund's program year 2023 match at $7,125,986.41, inside the authorization* (model mean 0.38). Certified at award grain with 74 obligations instead of 117 budget periods, putting the base at $35 to 37 million against $50,899,902.82.

## 3. Stops at a close but inexact match

**Decided 8 of 64 tasks, 5 of them under 0.50.**

**What the model does.** The current model avoids the obvious wrong measure and gets close to the published controls, then accepts the residual differences and moves on. The leader often survives, but the runner-up, the gap and the counts are wrong, and on thin margins the winner flips.

**What pulls it there.** A reconstruction that already ranks the right option first feels confirmed, and the one missing rule (a panel floor, a pre-storm screen, a size band) is not named in the prompt.

**What the data required.** Iterate the rule set until every control returns exactly (to six decimals, all nine values, all 16 entries), then apply it.

**How to build it.** Build the method from four to six rules, each documented somewhere in the folder or recoverable from the data. Publish enough controls that dropping any single rule breaks at least one. Make the runner-up or the margin depend on the last rule. Ask for the runner-up and the gap, not only the winner, so a near miss shows.

**How it goes wrong for authors.** If a dropped rule changes nothing the answer reports, the trap does not bite. If a rule is neither documented nor recoverable, the full stack becomes a guess.

**Where it happened.**

- *Project FY2026 Massachusetts 501(c)(3) revenue at USD 189.57 billion using the benchmark-certified 5.184732% growth rate* (model mean 0.42). Stopped at a 7,838-organization panel with no $100k floor and reported 5.227% growth against the certified 5.184732% measured over 4,719 organizations.
- *Certify Cocke County, Tennessee as the Hurricane Helene anchor county, with Buncombe County as runner-up* (model mean 0.53). Left out the pre-storm comparator screen, reporting Cocke at -5.44 and a 0.18-point gap against -5.51 and about 0.36.
- *Select Jurupa Unified School District for the cycle 3 fiscal diagnostic review* (model mean 0.41). Widened the peer pool for 2 systems instead of 8, so the winner held but Corpus Christi was named second instead of Lansing.
- *Refer the programme to the Board and withhold tranche 9* (model mean 0.57). Accepted a near match on the filed 2024-01A rate (0.3662 against 0.3655) and put the deciding difference at +6.10 to +7.42 against +7.183.

## 4. Never tests its reading against the control

**Decided 7 of 64 tasks, 5 of them under 0.50.**

**What the model does.** The current model picks one plausible reading of a step the rules leave open and computes on it without ever running it against the filed or settled figures in the folder. Those figures get treated as background, and some runs list the files that hold them as not used. The output is a confident table on the wrong basis.

**What pulls it there.** The control sits in a file that looks like history (a closed settlement, last year's register, a monitoring log) rather than in the instructions, and the rule text reads as complete enough to implement directly.

**What the data required.** Find the prior case or filed figure produced by the same process, test each candidate reading against it, and adopt the only reading that reproduces it.

**How to build it.** Leave one step of the method (a window, an attribution rule, an interval) unstated in the written standard. Ship a closed prior case or filed register produced by the same process, with figures exact enough to tell readings apart. Make the most natural reading miss that control by a visible amount. State in the governing documents that the standing method applies, so the control is plainly authoritative.

**How it goes wrong for authors.** If the folder never ties the control to the current method, a solver has no reason to use it and the task becomes a guess. Two readings that both fit the control leave the answer open.

## 5. Takes the population a flag or filter suggests

**Decided 5 of 64 tasks, 3 of them under 0.50.**

**What the model does.** The current model scopes the population by the filter a document names or the status a field shows. It counts slots marked available that are not yet in force, keeps a docket's officer-count filter, or treats a closeout book as every future closeout. The hidden rule that comes from dates or joins never gets applied.

**What pulls it there.** A status field, a named filter or a ready list looks like the definition, and nothing in the file flags the exceptions.

**What the data required.** Apply the rule as of the governing date or through the governing join (effective dates at the cutoff, release dates against a register, in-year arrivals from history) to get the true population.

**How to build it.** Give the population a defining rule that depends on a date or a join, not on a visible flag. Ship a field or list that agrees with that rule for most records but not all. Make the records it gets wrong large enough to move the decision. Put the governing date or register where a careful reader will find it.

**How it goes wrong for authors.** If the status flag is the only evidence and the governing rule is implied rather than stated, both scopes are defensible. Keep the exceptions checkable record by record.

## 6. Treats a mixed segment all one way

## 7. Uses the ready-made measure

## 8. Papers over a failed reproduction

**Decided 4 of 64 tasks, 4 of them under 0.50.**

**What the model does.** When its rebuild does not reproduce the published figures, the current model hides or sidesteps the gap instead of fixing the method. It pastes the published values into its own series, hard-codes the published bands, falls back to last year's schedule, or uses an escape clause to withhold the call.

**What pulls it there.** The misses look tiny (0.1 minute in a month) or the prompt offers a way out, so retreating feels compliant and safe.

**What the data required.** Every figure had to come from one method that reproduces the published values on its own. A published value cannot stand in for a computed one, and withholding was wrong because a reproducing method existed.

**How to build it.** Make the method recoverable from the published figures with a bounded search over a few unit, window or lag choices. Make the naive method miss by small amounts so pasting or rounding looks tempting. If you offer a withhold option, make sure the correct method does reproduce, so withholding is wrong. Ask for a script or a traceable series so pasted values show.

**How it goes wrong for authors.** An escape option that a careful analyst could reasonably take, because the method space is too large to search, makes the trap unfair. State the reproduction gate in the governing documents, not only in the prompt.

**Where it happened.**

- *Set the 2027 Team plan transcription allowance at 500 minutes per seat per month* (model mean 0.20). Its seat-based series matched 27 of 36 published months, and one run pasted the published values over FY2023 to FY2025 before recommending 575 minutes against 500.
- *Call the Gulf loading year to June 2026 loading-constrained at a 20.3979% congested share* (model mean 0.49). Reproduced 4 of 8 lifted readings, stopped searching and withheld the designation, when the year was loading-constrained at a 20.3979% congested share.

- *Report 11,667 stalls traded at member markets in the year to 31 March 2026* (model mean 0.21). Found its basis gave 91 capped markets against the printed 79, and one run hard-coded the published bands.

## 9. Picks from the offered options when none passes

**Decided 4 of 64 tasks, 3 of them under 0.50.**

**What the model does.** When every option offered fails the stated conditions, the current model picks the least bad one, refuses, or falls back to the status quo. It does not search the wider space the policy allows, or make the repair the rules require.

**What pulls it there.** The request lists a slate or a set of calls, which reads as the full choice set, and the policy's broader definition sits elsewhere.

**What the data required.** Read the policy's definition of an admissible option (any whole-thousand allowance, a retargeted cutoff side) and search that space.

**How to build it.** Offer a short slate in the request and define the admissible set more broadly in the policy. Make every slate option fail one stated condition. Make exactly one off-slate option pass all of them. Include clauses that rule out the veto and the status quo.

**How it goes wrong for authors.** If the policy does not clearly allow off-slate options, choosing from the slate is the right reading. Check that the off-slate answer is unique.

## 10. Notes a binding limit as a risk

**How to build it.** Frame the request around a primary metric. Put a constraint in a separate operational file that the governing policy says must hold. Make the unconstrained leader breach it. Ask for the final committed figure, not the projection.

## 11. Beats the headline trap, misses the quiet one

**Decided 4 of 64 tasks, 2 of them under 0.50.**

**What the model does.** The current model correctly rejects the trap the prompt makes prominent, then loses on a less visible step: a mirror collector, malformed rows, a guest-record link or a decoding step. Winning the visible fight seems to end its scrutiny.

**What pulls it there.** Once the headline decoy is beaten, the remaining steps look routine.

**What the data required.** Check every remaining step against its own control (prover controls, recovered malformed rows, phone-credited orders).

**How to build it.** Put one visible decoy in the prompt. Put a second, quieter contamination in the data that also changes the decision. Give the quiet trap its own control so it can be detected. Make sure beating only the first still gives a wrong answer.

**How it goes wrong for authors.** If the quiet trap has no control and depends on a convention the folder never states, missing it is not a fair failure.

## 12. Stops at the first control that passes

**What the model does.** The current model finds a construction that passes the most visible check and treats that as proof. It does not test the secondary controls that separate the candidate constructions, so it ships one that fails them.

**What pulls it there.** The headline control is passed cleanly, and because several constructions pass it, the remaining checks look redundant.

**What the data required.** Test every control in the folder (batch counts, neutral-band values, retained QA actions) and keep the only construction that passes all of them.

**How to build it.** Ship one salient control that several constructions pass, plus two or more finer controls that only the right one passes. Make the constructions that pass the salient control disagree on the decision. Keep the finer controls in the same archive so they are clearly part of the record.

**How it goes wrong for authors.** If the finer controls sit in an unrelated file or are described loosely, missing them is not a reasoning failure. Make sure the right construction passes the salient control too.

## 13. Validates on one population, applies to another

**Decided 3 of 64 tasks, 2 of them under 0.50.**

**What the model does.** The current model trusts a field or parameter because it fits the rows it can check, then applies it to rows that differ: unpaid awards whose dates were never re-aligned, commercial draws with a longer lag, or departures the sample under-covers.

**What pulls it there.** A clean backtest on historical or checked rows feels like proof.

**What the data required.** Ask whether the checked rows represent the rows being projected, and calibrate by subgroup where published aggregates show a difference.

**How to build it.** Make a field or rate fit the realized or sampled rows exactly. Make the forward or unsampled rows differ on one axis. Leave evidence of that difference in published aggregates or reference records. Make the difference change the decision.

**How it goes wrong for authors.** If nothing in the folder shows the forward rows differ, assuming they match is reasonable. The subgroup value must be recoverable exactly.

## 14. Coarsens the segment it was asked about

**What the data required.** Keep the segment at the grain the decision names (division by each rural-urban code, standard-rate trips, the division-chief review event) and quote the figures there.

**How to build it.** Name the segment with a term that has a common coarse shorthand. Ship the data at the fine grain and a convenience table at the coarse grain. Make the fine-grain answer change the decision. State the fine definition in a data dictionary or standard.

**How it goes wrong for authors.** If the wording genuinely admits both grains and nothing in the folder fixes it, the coarse answer is defensible. Spell out the class list somewhere authoritative.

**Where it happened.**
