Data messiness
Layer 1 of every task. How to make the inputs genuinely messy, hard to parse and hard to understand, the way real data is, without planting defects or decoys.

Real data is hard to use before any analysis starts. A strong task makes the solver put it in order: parse native formats, reshape, join across sources with imperfect keys, reconcile overlapping releases and harmonise units, vintages and classifications. This is Layer 1 of Two-layer task design. It should cost the solver time and care, but it should never be what decides the answer; that is Layer 2, on Stumping strategies. The package rules (file counts, the large CSVs, distractors) are on Input files.

Messy is not the same as planted
The test for any messiness: would a real analyst meet it in the real source? If it exists only so that catching it flips the answer, it is a planted defect, not Layer 1. That rules out copied or backfilled blocks, swapped or reversed series, a hidden year-to-date column, deliberately wrong totals, mislabelled fields planted to mislead, and decoy memos or staff drafts written to carry the wrong answer.

Techniques that work in every field
Native release formats. Use files as the publisher ships them: multi-sheet workbooks with title blocks, merged headers and footnote markers, PDFs with tables, fixed-width or layout files that change across years. The solver has to read and reshape before analysing.
Several sources for one picture. Spread the evidence across files that were never designed to join: a registry, a periodic release, a filing and a log. Each has its own keys, grain and timing.
Imperfect keys. Codes in one file and names in another, identifiers that change between systems or years, entities under several spellings, and many-to-many links that need a stated rule.
Vintages and revisions. A preliminary and a revised release that overlap, classification or boundary changes between years, and crosswalks that split or merge units.
Units, time and scale. Fiscal and calendar years, local time and UTC, nominal and real values, counts and rates on different bases, values in thousands in one file and units in another.
Genuine overlap. Extracts that cover overlapping periods, records resubmitted after correction, and the same event reported by two parties. Deduplication needs a rule a careful analyst would apply.
Real coverage and missingness. Suppressed small cells, survey skip and reserve codes, partial years, entities that enter or exit, and reporting thresholds. These are documented features of the source, not inserted holes.
Documentation that has to be read. Codebooks, data dictionaries, release notes and methodology statements the solver must apply to interpret fields correctly.
Keep it honest
State or ship whatever a careful analyst needs to resolve each kind of mess: the codebook, the crosswalk, the release note. The mess should reward care, not hide the answer, and the cleaned data should support exactly one recommendation once Layer 2 is done right.

Product Analytics (8)
1Event names and properties drift across releases
Client versions rename events, add or retire properties, and change property types. The solver must map old and new names onto one taxonomy before counting anything across the release boundary.
Where it occurs
Product event logs spanning several app versions, tracking plans with changelogs.
Keep it honest
Record each rename in a tracking plan changelog and let old and new names overlap in time so the mapping is recoverable.
2Anonymous devices stitched to signed-in users
The same person appears as a device id before login and a user id after, often on several devices. The solver must merge identities through a mapping table and decide the unit of analysis.
Where it occurs
Web and mobile event logs with identify calls, identity resolution and alias tables.
Keep it honest
Supply the identity map and say in the brief whether the metric is per user or per device.
3Client clocks, server clocks and offline batches
Client timestamps skew, offline events upload hours later, and users sit in different time zones. The solver must pick the right clock, convert zones and sessionize without splitting real sessions.
Where it occurs
Mobile SDK logs carrying both client and server timestamps, offline-capable apps.
Keep it honest
Keep both timestamp columns clearly named; the question's window definition states which clock and time zone count.
4Retried and double-fired events
SDK retries resend events with the same insert id and some screens fire a view twice on load. The solver must dedupe on the event id, not on matching content, before computing rates.
Where it occurs
Raw client event streams with at-least-once delivery, warehouse event tables.
Keep it honest
Give every event an insert or message id and keep the duplicate share at a low, realistic level.
5Assignment, exposure and outcomes in separate tables
Experiment bucketing, actual exposure and outcome events live apart; some users are assigned but never exposed, and a few appear in both arms across devices. The solver joins and applies the exposure rule.
Where it occurs
Feature flag and experimentation platform exports, assignment and exposure logs.
Keep it honest
Describe the exposure and analysis rule in the experiment spec and keep the rare cross-arm users identifiable from the logs.
6Nested JSON properties inside event rows
Event properties sit in a JSON string column with nested arrays such as cart items, optional keys and types that shift by version. The solver must flatten, explode arrays and cast types.
Where it occurs
Warehouse exports of event tables with a properties or context JSON column.
Keep it honest
Keep the JSON valid, document keys in the tracking plan, and tie type changes to real version changes.
7Internal, test and bot traffic mixed in
Employee accounts, QA devices, load tests and crawlers sit alongside real users. The solver must filter them using an internal account list, test flags and user agent strings before measuring adoption.
Where it occurs
Web analytics logs, product event streams, signup and account tables.
Keep it honest
Provide the internal account list or flag column and state the exclusion rule in the metric definitions doc.
8Billing events reconciled to product accounts
The billing system records trials, upgrades, prorations and refunds under its own customer ids and currencies. The solver must link them to product accounts before computing retention or revenue per user.
Where it occurs
Billing processor exports alongside product usage logs and CRM account tables.
Keep it honest
Supply the account crosswalk and a short billing glossary so prorations and refunds follow normal billing semantics.

Quantitative Finance (8)
1Unadjusted prices around splits and dividends
Raw exchange prices jump at splits, reverse splits and special dividends. The solver must build adjustment factors from a separate corporate actions file and apply them before computing any returns.
Where it occurs
Exchange end of day files, vendor price histories, corporate action notices and dividend announcements.
Keep it honest
Ship the actions file with real ex-dates. The answer should need correct adjustment, never discovery of an unrecorded split.
2Ticker reuse and identifier changes over time
Tickers get reused, and firms change names, security codes or listing venues. The solver must link each security's history through a dated identifier map instead of joining on the ticker string.
Where it occurs
Security master files, index constituent histories, fund holdings filings and exchange listing notices.
Keep it honest
Provide the dated map with real effective dates so ticker-only joins show visible mismatches rather than silently wrong answers.
3Delisting events kept outside the price file
Securities that delist simply stop appearing in the daily price file; final delisting returns and reason codes sit in a separate events table that must be merged into the return panel.
Where it occurs
Academic stock return databases, exchange delisting notices and index deletion histories.
Keep it honest
Keep delistings at their natural frequency and document the events table in the readme; never drop it to hide the effect.
4Trade and quote clocks in mixed zones
Tick data from different venues uses local exchange time, UTC or sequence numbers at varying precision. The solver must normalise clocks, handle daylight saving shifts and match trades to prevailing quotes.
Where it occurs
Consolidated tape extracts, venue trade logs, quote files and order book snapshots.
Keep it honest
Use the precision and zone conventions each source actually documents, and state them in a readme rather than hiding offsets.
5Trading calendars that differ across markets
Markets close on different holidays and half days. The solver must align multi-market panels on a common calendar and handle stale or missing prices without inventing returns on closed days.
Where it occurs
International equity, futures and currency daily files alongside published exchange holiday calendars.
Keep it honest
Include the real calendars; the stated method should say how to align dates so the choice is pinned, not guessed.
6Separate futures contracts needing a continuous series
Futures arrive as individual expiring contracts with overlapping dates, volumes and open interest. The solver must stitch a continuous series under a roll rule and treat the price gap at each roll.
Where it occurs
Exchange settlement files, futures contract histories and vendor term structure extracts.
Keep it honest
State the roll rule in the prompt or a spec, and supply every contract file so stitching is work, not guesswork.
7Mixed price and rate quoting conventions
Bonds are quoted clean in fractions, rates in percent or basis points, currencies in direct or indirect terms, options in volatility or premium. The solver must convert everything to one convention before combining.
Where it occurs
Dealer quote sheets, fixed income pricing files, currency rate tables and option chain extracts.
Keep it honest
Label each convention in headers or a readme as real sources do, so the work is conversion, not decoding a riddle.
8Holdings filings with reporting lags and amendments
Portfolio holdings come from periodic filings released weeks after period end, and amended filings supersede originals. The solver must use what was known on each date and keep the latest valid version.
Where it occurs
Regulatory fund holdings filings, institutional manager position reports and fund factsheets.
Keep it honest
Include originals and amendments with real filing dates; the prompt should define the as-of rule so look-ahead is avoidable.

Banking, Credit & Financial Risk (8)
1Monthly loan tapes with status transitions
Servicer files repeat each loan every month with delinquency status codes. The solver must reshape snapshots into loan histories, apply the status codebook and handle loans that pay off, transfer or reappear.
Where it occurs
Securitisation loan level disclosures, servicer performance files and agency mortgage performance datasets.
Keep it honest
Supply the real status codebook, and let transfers and payoffs occur at natural rates rather than inserting gaps as traps.
2Regulatory report line items renumbered across revisions
Bank regulatory reports renumber, split or merge line items when forms are revised. The solver must build a crosswalk across form vintages before computing capital, liquidity or asset quality ratios over time.
Where it occurs
Quarterly bank regulatory filings, supervisory financial reports and form instruction manuals with revision notes.
Keep it honest
Provide the instructions or revision notes so the crosswalk is derivable from the documents, not guessed.
3Mergers and charter changes reshaping entities
Institutions merge, convert charters and move between holding companies. The solver must follow a structure history to aggregate subsidiaries correctly and avoid double counting acquired balances or losing predecessor history.
Where it occurs
Bank structure and attribute histories, merger transaction databases and holding company filings.
Keep it honest
Include the structure history with real effective dates; mergers should be ordinary texture, not a hidden switch that flips totals.
4Bureau attributes carrying special value codes
Credit attributes use sentinel values for no trade, not applicable or inquiry only, sitting in the same numeric column as real counts. The solver must decode them from the dictionary before averaging or modelling.
Where it occurs
Credit bureau attribute extracts, scorecard development samples and lender application files.
Keep it honest
Document every sentinel in the data dictionary exactly as a bureau would; never leave one undocumented to catch the solver.
5Ratings on different agency scales and outlooks
Ratings arrive as letter grades with modifiers, watches and outlooks from several agencies. The solver must map them to one ordinal scale and pick the rating in force on each date.
Where it occurs
Agency rating action histories, issuer rating files and regulatory rating disclosures.
Keep it honest
Supply a real mapping convention or name the one to use, so the scale choice is pinned by the spec.
6Charge-offs and recoveries booked in different periods
Losses appear as gross charge-offs, then recoveries arrive later in a separate collections file. The solver must match recoveries back to loans or vintages to compute net loss on the right basis.
Where it occurs
Loan servicing ledgers, collections and recovery files, and bank loss disclosures.
Keep it honest
Keep recovery lags realistic for the product, and state whether net loss is measured by vintage or by period.
7Transaction logs with reversals and chargebacks
Payment and card logs hold authorisations, settlements, reversals and chargebacks for the same purchase as separate rows. The solver must link event types into one transaction before measuring volumes, losses or fraud rates.
Where it occurs
Card processor extracts, core banking transaction logs and payment network settlement reports.
Keep it honest
Use the event codes and linking keys real processors provide, at natural frequencies; do not plant phantom duplicates.
8Rates quoted on different bases and day counts
Loan and deposit rates appear as nominal or effective annual rates, on different day count bases and compounding frequencies. The solver must harmonise them before comparing yields or computing interest income.
Where it occurs
Loan origination systems, deposit rate sheets, pricing disclosures and treasury funding files.
Keep it honest
Label each basis as the source does; the work should be conversion, not guessing an unstated convention that decides the answer.

Actuarial Science & Insurance (8)
1Claim transactions needing triangle construction
Claims arrive as payment and reserve transactions with accident, report and payment dates. The solver must aggregate them into accident period by development age, handling reopened claims and reserve changes.
Where it occurs
Claims system extracts, statutory loss development schedules and reinsurance claim bordereaux.
Keep it honest
Give transaction-level data with a clear date dictionary; the method chosen on the triangle should decide the answer, not hidden rows.
2Endorsements and cancellations altering earned exposure
Policies change mid-term through endorsements, cancellations and reinstatements recorded as separate transactions. The solver must rebuild in-force periods to compute earned premium and earned exposure correctly.
Where it occurs
Policy administration extracts, premium bordereaux and rating system transaction logs.
Keep it honest
Use transaction types and effective dates as a real policy system records them, at natural frequencies.
3Accident, policy and calendar year bases mixed
Different reports group losses by accident year, policy year, underwriting year or calendar year. The solver must identify each basis and align or convert before comparing loss ratios or development.
Where it occurs
Statutory annual statements, reinsurance submissions, internal management reports and rate filings.
Keep it honest
Label the basis on each report as the source would; the question should name the basis the answer uses.
4Mortality and lapse tables in published grid layouts
Standard and experience tables come as wide select and ultimate grids by age and duration, with header notes and footnotes. The solver must reshape to long form and key by issue age and duration.
Where it occurs
Published mortality tables, industry experience study reports and regulatory valuation tables.
Keep it honest
Keep the native published layout and notes; the table should be usable once reshaped, with no altered cells.
5Bordereaux in differing coverholder layouts
Each coverholder or cedant sends periodic bordereaux with its own column names, currencies and coding, plus resubmitted periods. The solver must map all of them to one schema and dedupe genuine resubmissions.
Where it occurs
Delegated authority bordereaux, reinsurance treaty statements and managing agent submissions.
Keep it honest
Make resubmissions look like real corrected sends with dates; the solver keeps the latest by a documented rule.
6Peril and cause of loss codes revised
Peril and cause of loss codes change when claim systems migrate or coding schemes are revised. The solver must apply a code crosswalk so each peril is counted consistently across years.
Where it occurs
Claims system extracts across migrations, statistical agent reporting plans and coding manuals.
Keep it honest
Provide the crosswalk or manual revision notes; unmapped codes should be few and documented, not planted.
7Catastrophe claims assigned to events by window
Catastrophe claims carry event codes assigned by different bodies with differing date windows and areas. The solver must assign claims to events by loss date and location under the stated event definition.
Where it occurs
Claims extracts, catastrophe event registries, reinsurance event loss reports and hours clauses.
Keep it honest
State the event definition and window; let some claims fall near boundaries naturally rather than placing them to flip totals.
8Member census files across valuation dates
Pension and group benefit censuses give member snapshots at each valuation. The solver must match members across dates, infer exits, retirements and deaths, and reconcile them with benefit payment records.
Where it occurs
Pension plan valuation censuses, group benefit enrolment files and payroll or benefit payment extracts.
Keep it honest
Keep identifier changes and data gaps at realistic rates and document matching keys; do not hide decisive deaths.

General Statistics & Data Science (8)
1Results reported under inconsistent conventions
Results tables mix percent and fraction, best seed and mean of seeds, and different evaluation splits. The solver must harmonise conventions before ranking methods.
Where it occurs
Results tables in papers, leaderboard snapshots, experiment tracker exports.
Keep it honest
Label seed count, aggregation and split in every source; never change a convention without saying so.
2Resumed and crashed training runs
Runs restart from checkpoints and repeat steps, crashed runs stop early and step counters reset. The solver must stitch each run's history and pick the right final metric.
Where it occurs
Experiment tracker step logs, per-step metric CSVs, scheduler job records.
Keep it honest
Carry run and resume ids with timestamps so overlapping steps can be resolved by a stated rule.
3Dataset versions and split manifests
Datasets get revised with removed or relabelled examples, and train, validation and test membership lives in separate id lists. The solver must join examples to the correct version and split.
Where it occurs
Versioned dataset releases with changelogs, split manifests and removal lists.
Keep it honest
Ship the changelog and have the question name the version being evaluated.
4Multi-rater annotations with adjudication
Labels arrive per rater in long format, guidelines change between rounds and adjudicated labels sit in a separate table. The solver must aggregate to one label per item by the stated rule.
Where it occurs
Crowdsourcing platform exports, annotation tool exports, adjudication tables.
Keep it honest
Document the guideline version per round and the aggregation or adjudication rule.
5Nested configs with implicit defaults
Sweep configs inherit from base files and omit default values, so effective hyperparameters are not written anywhere directly. The solver must resolve configs before grouping runs.
Where it occurs
Sweep configuration files, experiment tracker config exports, run metadata.
Keep it honest
Include the base and default config files so every effective value is recoverable.
6Large per-example prediction dumps
Evaluation outputs list per-class scores for many examples, with integer class indices and a separate label map. The solver must align indices, labels and ground truth before scoring.
Where it occurs
Model evaluation output files, batch inference logs, prediction CSVs.
Keep it honest
Ship the label index map and keep ordering consistent with it.
7Compute logs in mixed units and hardware
Compute is recorded as GPU hours, accelerator days or wall clock across different hardware types and node counts. The solver must normalise to one unit before comparing cost.
Where it occurs
Cluster scheduler logs, cloud billing exports, training reports.
Keep it honest
State hardware type and device count per job and supply any conversion factors used.
8Near-duplicate examples across splits
Scraped or augmented data contains genuine near duplicates across train and test. The solver must use the provided content hashes to flag overlap and apply the stated evaluation protocol.
Where it occurs
Web-scraped corpora, dataset deduplication reports, content hash tables.
Keep it honest
Keep overlap at a realistic low rate and state in the protocol how overlapping items are handled.

Biomedical & Clinical Research (8)
1Trial data split across domain tables
Subject data arrives as separate demographics, exposure, visit, lab and adverse event tables keyed by subject and visit. The solver must join them, pivot long lab records and build one analysis row per subject.
Where it occurs
Clinical trial data transfers, standardised submission datasets, investigator site exports, sponsor data listings.
Keep it honest
Supply the key structure and a data dictionary; make the joins real work but unambiguous, with every subject traceable across tables.
2Lab results in mixed units and ranges
Local and central labs report the same analyte in different units with site-specific normal ranges. The solver must harmonise units, map flags to a common range and decide which lab feeds the endpoint.
Where it occurs
Multicentre trial lab transfers, hospital lab extracts, biobank assay results, registry lab feeds.
Keep it honest
Give unit labels and the conversion source or range table; the protocol should say which lab is primary so no guessing decides it.
3Unscheduled and out-of-window visits
Visit labels mix nominal names, unscheduled repeats and early termination records, and actual dates drift from schedule. The solver must compute study day and map each record to analysis windows.
Where it occurs
Trial visit logs, case report form exports, longitudinal cohort follow-up records, clinic encounter extracts.
Keep it honest
State the windowing rule in the protocol or analysis plan; keep drift realistic so careful mapping, not a hidden rule, gets it right.
4Partial dates needing stated imputation
Onset, diagnosis and medication dates are recorded with unknown day or month. The solver must apply the stated partial-date imputation convention before computing durations, exposure or time to event.
Where it occurs
Adverse event and medication case forms, medical history pages, patient-reported diaries, retrospective chart abstraction.
Keep it honest
Include the imputation convention in the analysis plan; keep partial dates at realistic frequency and make the rule, applied correctly, determine durations.
5Verbatim terms coded to a dictionary
Adverse events and medical history arrive as investigator verbatim text alongside dictionary codes, sometimes from different dictionary versions. The solver must group terms at the right hierarchy level and reconcile version changes.
Where it occurs
Safety databases, trial adverse event listings, pharmacovigilance case exports, coded medical history tables.
Keep it honest
Provide the coding map or hierarchy file; mismatches should reflect real version drift and synonyms, not deliberately miscoded events.
6Free-text concomitant medication records
Medication entries mix brand and generic names, combined dose and frequency strings and abbreviated routes. The solver must parse dose, standardise drug names and assign each entry to a class or exposure period.
Where it occurs
Concomitant medication case forms, pharmacy dispensing logs, electronic health record medication lists.
Keep it honest
Offer a drug name or class lookup; spelling and format variety should be real clinical entry habits that careful parsing fully resolves.
7Assay values beyond quantification limits
Biomarker and drug concentration results include below-limit and above-limit codes, repeat assays and failed samples flagged by the lab. The solver must apply the stated handling for censored values and choose among repeats.
Where it occurs
Bioanalytical lab reports, pharmacokinetic sample listings, biomarker panels, central lab result transfers with sample condition comments.
Keep it honest
Document the limits and repeat-selection rule in the lab manual or plan; keep codes in native lab form, never silently replaced.
8Questionnaire items needing a scoring manual
Patient-reported outcome data comes item by item with reverse-scored items, allowed missing items per scale and form versions. The solver must score scales per the manual before analysing change from baseline.
Where it occurs
Patient-reported outcome exports, quality of life instruments, symptom diaries, electronic clinical outcome assessment platforms.
Keep it honest
Ship the scoring manual as an input; item missingness should follow real completion patterns and the manual's rules should settle every case.

Epidemiology & Public Health (8)
1Small-cell suppression in surveillance tables
Published counts below a confidentiality threshold appear as symbols or ranges, with complementary suppression in totals. The solver must carry suppressed cells honestly, use available margins and avoid treating them as zero.
Where it occurs
Surveillance summary tables, cancer and birth defect registries, vital statistics tabulations, small-area health profiles.
Keep it honest
Explain the suppression rule in footnotes; ensure the decision rests on unsuppressed cells or margins, not on guessing hidden values.
2Preliminary counts revised by later releases
Weekly case or death counts are reported provisionally and filled in by later releases as delayed reports arrive. The solver must pick the right vintage per week and handle reporting lag near the end.
Where it occurs
Weekly notifiable disease reports, provisional mortality releases, syndromic surveillance feeds, outbreak situation report series.
Keep it honest
Label each release date clearly and state which vintage the question uses; revisions should follow real backfill patterns, not invented reversals.
3Denominators from mismatched population vintages
Case data uses one set of age bands and years while population estimates come in other bands and vintages. The solver must align age groups, choose the stated estimate series and build rates.
Where it occurs
Population estimate releases, intercensal and postcensal series, census age tables, health department rate tables.
Keep it honest
Name the required denominator series in the prompt or a methods note; make band alignment real work with one correct mapping.
4Geographic codes changing over time
Counties, districts or health areas split, merge or get renamed, and some sources use names while others use codes. The solver must apply a crosswalk, including allocation factors for postal-code to area links.
Where it occurs
Boundary change notices, postal-code crosswalks, administrative area code lists, state and local surveillance files.
Keep it honest
Supply the official crosswalk or allocation table; changes should be ones that genuinely occur, and the allocation rule should be stated.
5Case definitions and coding revisions
Case definitions add probable categories or tighten criteria, and cause-of-death coding moves between classification revisions. The solver must separate confirmed from probable and apply comparability adjustments across the break.
Where it occurs
Notifiable condition case files, mortality multiple-cause files spanning coding revisions, disease registry case status fields.
Keep it honest
Include the definition history or comparability ratios; the break should be documented in the source, and the question should say which definition counts.
6Survey microdata with design and skip codes
Health survey records carry weights, strata, clusters and numeric codes for refused, don't know and not asked. The solver must recode missing codes and use the design variables for estimates.
Where it occurs
National and state health interview surveys, behavioural risk surveys, household health and nutrition examination surveys.
Keep it honest
Ship the codebook with design notes; skip patterns should follow the real questionnaire flow, and the stated estimator should be unique.
7Overlapping case reports across jurisdictions
The same person can be reported by residence and by diagnosing jurisdiction, or appear again as a reinfection or update. The solver must deduplicate with the stated matching and episode rules.
Where it occurs
Surveillance line lists, interjurisdictional case exchange extracts, laboratory electronic reports, immunisation registries.
Keep it honest
State the deduplication and episode window rules; overlap should be the natural kind found in shared surveillance, not copied blocks.
8Rates on different bases and standards
Sources publish crude, age-specific and age-adjusted rates per different population bases and against different standard populations. The solver must convert bases and re-standardise to one stated standard before comparing.
Where it occurs
Health statistics compendiums, registry annual reports, mortality rate tables, community health assessment profiles.
Keep it honest
Provide the standard population weights and say which standard applies; labels must state the base honestly so careful reading resolves it.

Pharmacology, Pharmacoepidemiology & Safety (8)
1Package codes mapped to active ingredients
Dispensing records identify products by package level codes in mixed 10 and 11 digit formats, brand names and salt forms. The solver must normalise code formats and map each package to ingredient and strength through a product crosswalk.
Where it occurs
Pharmacy claims extracts, drug product directories, retail dispensing files, formulary listings across several years.
Keep it honest
Ship the real product directory alongside; leave unmatched or discontinued codes as they occur, and state which ingredient level the question counts.
2Overlapping fills, early refills and reversed claims
Prescription claims include early refills that overlap prior supply, missing or implausible days supply, and reversal rows that cancel paid claims. The solver must net reversals and stitch fills into continuous exposure records before counting use.
Where it occurs
Adjudicated pharmacy claims, outpatient dispensing logs, insurer drug utilisation files.
Keep it honest
Keep reversals and overlaps at realistic rates; state the stockpiling and grace period rule in the prompt so episode building is deterministic.
3Spontaneous reports with versions and duplicates
Safety case reports arrive as an initial version plus follow ups, and the same event may be reported by a manufacturer and a clinician. The solver must keep the latest version per case and merge genuine duplicates.
Where it occurs
Spontaneous adverse event reporting databases, manufacturer safety submissions, regulator case line listings.
Keep it honest
Include the case and version identifiers the real system carries; duplicates should be ones a standard case matching rule resolves, not disguised copies.
4Verbatim reaction terms and coding dictionary versions
Reactions appear as reporter verbatims or as preferred terms from older dictionary versions. The solver must map them to the current hierarchy and roll up to the level the question asks about, such as organ class.
Where it occurs
Adverse event report files, trial adverse event listings, post marketing safety tables coded over many years.
Keep it honest
Supply the term hierarchy file; leave real misspellings and legacy terms, and name the hierarchy level used for counting in the prompt.
5Strength strings, combination products and dose units
Strength fields read like text, such as amount per volume, per actuation or combined ingredient pairs, in mg, mcg or units. The solver must parse them into numeric ingredient amounts to compute daily or cumulative dose.
Where it occurs
Drug product listings, dispensing records, inpatient medication administration logs, trial dosing records.
Keep it honest
Use the genuine string formats of the source; state the dose metric and any reference dose conversion the analysis must apply.
6Lab results with mixed units and reference ranges
Liver and kidney markers come from many labs in different units, each with its own upper limit of normal. The solver must convert units and express values as multiples of each lab's limit before flagging safety thresholds.
Where it occurs
Trial laboratory datasets, electronic health record result tables, hepatotoxicity and renal safety reviews.
Keep it honest
Carry each lab's reported range on the row; state the threshold definition, so converting correctly matters but nothing is hidden.
7Monthly enrolment flags into eligibility spans
Coverage arrives as one row per member month or as start and end segments with gaps and plan switches. The solver must build continuous enrolment spans to decide who has the required baseline and follow up time.
Where it occurs
Insurance enrolment files, claims database member tables, public program eligibility extracts.
Keep it honest
Keep genuine gaps and plan changes; state the allowable gap and baseline length so span building is the work, not a guess.
8Partial and inconsistent dates in case records
Onset, start and stop dates in safety records are often year only or month and year, and receipt dates differ from event dates. The solver must order events and compute time to onset under a stated imputation convention.
Where it occurs
Spontaneous report line listings, trial adverse event and concomitant medication records, chart abstraction files.
Keep it honest
Use partial dates at realistic frequency; state the imputation rule in the prompt or a supplied conventions document so results are reproducible.
